## 10. 実装運用

原則:

1. 実装前に他AgentのPR・branch・Scopeを確認。
2. 1 PR = 1目的。
3. shared契約を変更する場合は、先に契約影響を確認。
4. 実装 → selftest/typecheck → build → PR → CI → 風紀委員確認 → merge → Pages deploy → 実機確認。
5. 新規失敗は既存案件と混ぜず独立して切り分ける。
6. 完了した項目を繰り返し修正しない。
7. 分割は手段であり、目的ではない。
