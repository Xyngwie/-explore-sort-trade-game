# 出撃をまたぐ地面盾・剥離進捗の保存（#312）

## 基準・確定回答

main `3a524fd`（#311）、公開デプロイ39372330509成功。ブランチ `cursor/codex-field-shield-persistence`。

神宮の2026-10-20回答：

- Q1=A：保存先は同じInvade盤面（seed）の同じマス。別マスとは共有せず、盤面再生成で地面盾は消える。
- 直接出撃に関する補足：EXPLOREとINVADEで同じ盤面を使う。INVADEを通らない入口も、同じ盤面に未踏査で入る扱い。「直接出撃では永続化しない」という旧Q2案は撤回。
- 差し替えQ2=A：直接出撃はHQ（0,0）から出発。既存の踏査・旗・選択マスを変更しない。

- Q3=A：剥離を開始した敵残骸だけ残す。未着手の敵残骸は従来どおり出撃ごとに生成する。味方残骸は既存lostMechsのまま。今回の確認事項はすべて解消。

## 今回の実装範囲

- 地面盾の正確なHP・座標・個体ID・出自・生成順、剥離途中の残骸と回路・進捗を、帰還保存と同じマスへの再出撃へ接続。
- 剥離開始済みの敵残骸は元の回路データのまま復元。新しく出現する生きた敵は従来どおり毎出撃ランダム。剥離・回収した残骸は再出現させない。復元した敵残骸から弾薬・電力を再生成しない。
- 味方残骸は既存lostMechsと重複保存せず、剥離進捗の参照を元の機体instanceIdに対応させる。runtimeのwing-a等からs:<instanceId>へ参照を変換。旧航空支援の匿名残骸も互換復元。
- 回収・交換・剥離の作業者予約を次の出撃へ持ち越さない。剥離の秒数は残す。
- 同じマスのスナップショットを置換し、空の報告も反映する。他マスは維持。sortieIdで二重適用を防ぐ。
- 盤面再生成では地面盾と今回の残骸進捗参照を消すが、既存lostMechsの移動規則は変更しない。IDカウンターを巻き戻さない。旧盤面からの遅れた報告を無視する。
- ブラウザーで結果再読込→再出撃のマス情報欠落を再現。URLから除去済みでもcheckpointのInvade情報から再出撃リンクを復元する。
- 結果checkpointで敵一覧を省く前に帰還用データを保持し、保存拒否後の再読込・再試行でも残骸情報を失わない。#312以前の結果checkpointから空の新形式報告を作らない。

## 入口と盤面共有

既存の盤面生成・復元ロジックをsharedへ移し、Invadeの既存import先は互換再exportとする。生成アルゴリズムと既存テストの期待値は変更しない。

直接出撃に盤面がなければseed・空の踏査/旗情報をHubSaveへ先に保存する。既存盤面があればそのseedを使い、HQの周辺敵数を同じ生成処理で解決する。新たな踏査は行わない。保存拒否なら出撃を止め、保存後の再読込を案内する。HubSaveのない単独デモでは新しい保存データを勝手に作らない。既存checkpointの出撃を入口変更で上書きしない。

これは現行のマス単位の保存と入口の接続であり、盤面全体を歩く統一マップ、1対1、600秒化、権威サーバーの完成を意味しない。

## 保存契約

HubSave v3の任意fieldCellsと既存fieldObjectIdentitiesを使用。各マスはlocation（frontSeed・cell）、ground（安定キー→座標）、wrecks（安定キー・位置・出自・進捗・回路/敵残骸の素体）を保持する。盾のHP/IDは正規レジストリだけに置く。

帰還payloadの任意fieldCellは当該マスの参照レコード・必要な正規IDレコード・カウンターを含む。URLと直接保存の両方が共通精算を使う。payloadのfrontSeed/cellとの一致と現在の盤面seedを確認する。参照切れなどの不正なセーブは、物体を黙って削除せず読込拒否する。
