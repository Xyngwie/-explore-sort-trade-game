対象main `7efe66c460973023a16bcb8dddb8bdb4e55e211a`。公開入口：https://xyngwie.github.io/-explore-sort-trade-game/

実行者、日時、対象URL/commit、端末/OS/ブラウザー/画面寸法、セーブ準備方法、各操作の結果と画像を残す。ローカル、自動ブラウザーでの公開版操作、公開版の人による手動操作、物理スマートフォンは**別欄**とする。実行していない欄をPASSにしない。通常セーブのバックアップを取り、隔離したブラウザープロファイルで行う。

P盾/通常盾回路や盾がない通常セーブでは、一連の操作をすべて確認できない。準備できない項目は未実施として報告し、稀な回路の取得待ちを検証完了としない。公開版へテスト用付与機能を追加しない。エージェントは既存スクリプトの隔離checkpoint fixtureを使用できるが、取得バランスや通常ランダム通しプレイの検証とは区別する。

各終了/再開時は、同じIDが地面/装備/予備/設置の複数箇所にないこと、盾総数の増減に生成・破壊・剥離/帰還の根拠があることを確認する。隔離fixtureではcheckpointとHubSaveを比較し、手動確認では同じ対象の回収/表示の二重化を記録する。

不一致は操作前後の保存情報と最短再現手順を添える。未再現の観測は「未確認」。新しい仕様判断が必要ならSPEC_QUESTIONに戻し、期待値を書き換えて解決したことにしない。

## エージェント向け再実行

Node 20以上、`npm ci`、Explore5173/Trade5175/Invade5176を起動。`PLAYWRIGHT_MODULE`と`CHROMIUM_PATH`は環境の実パスを指定する。既存の8本の`verify-*.cjs`を順に実行し、同時実行によるシミュレーションの待ち時間超過を避ける。

公開版の屹立経路も確認する場合：

```sh
FIXTURE_BASE_URL=http://127.0.0.1:5173 \
EXPLORE_BASE_URL=https://xyngwie.github.io/-explore-sort-trade-game/explore \
PLAYWRIGHT_MODULE=/path/to/playwright-core \
node scripts/verify-barricades.cjs
```

fixtureの作成だけローカルを使い、その後のボタン操作・シミュレーション・保存/復元は公開配信のJavaScriptで実行する。人による手動確認や物理実機と呼ばない。
