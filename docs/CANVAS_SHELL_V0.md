# 単一 canvas 刷新・第1段階（CANVAS_SHELL_V0）

（続き：全モジュールの 1 ページ統合は [CANVAS_UNIFIED_V0.md](CANVAS_UNIFIED_V0.md)。DOCK の残りはそちらで実装した。）

ゲーム全体を一枚の canvas で描画・操作するための基盤と、DOCK の一部分（所持資源 HUD・未開封コンテナ数・物資市場の購入）。既存版はそのまま残し、比較用に別の入口から起動する。

状態：第1段階の実装。§7 の細部 CANVAS-D1〜D11 は、すべて★推奨のとおり神宮決定（2026-11-04）。

### 3.1 描画と状態の分離

- 即時モード：毎フレーム、シーンが自分を描き、同時にボタン等の当たり判定の領域を登録する。入力は、直前に描いたフレームの領域で判定する。描いた位置と当たる位置は同じ計算から出るので、ずれない。
- 描画は状態を読むだけ。保存・取引は、ボタンを離したときに呼ばれる `onActivate` の中だけで起こる。再描画・リサイズ・回転では保存しない（selftest と verify で確認）。
- 再描画は必要なときだけ（入力・リサイズ・保存の変化）。タイマーで描き続けない。

### 3.2 座標・高 DPI・リサイズ

- シーンは CSS ピクセルで描く。canvas の実ピクセルは `round(CSS 幅 × devicePixelRatio)`。描画時に縮尺を掛ける。
- 入力は `clientX/Y − canvas の左上` を CSS ピクセルへ直して判定する（canvas が CSS で伸びていても比で戻す）。
- `resize`・`visualViewport` の resize・`orientationchange`・ResizeObserver で作り直す。DPR が変わった（ズーム、別の画面へ移動）ときも作り直す。
- ノッチ等の安全領域（`env(safe-area-inset-*)`）を読み取り、HUD と一覧を内側へ置く。
- 列の最大幅は既存シェルと同じ 960px（§7 CANVAS-D10）。

### 3.3 入力の優先順位

1. プレイ記録の保存中・保存失敗中（`playLogBlocked()`）は、どのボタンも発火しない。既存の画面（§8）が前面に出る。
2. モーダル（確認ダイアログ）が開いている間は、モーダルの層だけが入力を受ける。下のボタンは押せない。外側のタップは「やめる」と同じ（CANVAS-D6、神宮決定 2026-11-04）。Escape も同じ。
3. スクロール領域の中では、押してから縦に 8px を超えて動いたらスクロールになり、そのボタンは発火しない（指を戻しても発火しない）。
4. ボタンは、押した場所と離した場所が同じボタンのときだけ発火する。外へずらすと取り消し。
5. `pointercancel`・ポインターの捕捉が外れた・ウィンドウのフォーカスが外れた・タブが隠れた、のどれでも押下は取り消し（発火しない）。
6. 2 本目の指が触れたら、1 本目の押下も取り消し、2 本目も無視する（二本指での誤購入を防ぐ）。触れている指をすべて覚え、1 本でも残っている間は新しい押下を受け付けない（2026-11-05 修正、[CANVAS_UNIFIED_V0.md §12](CANVAS_UNIFIED_V0.md)）。
7. ボタンの発火は、離した 1 回につき 1 回。購入は 1 回につき保存 1 回・記録 1 件。保存が始まるとプレイ記録が入力を止めるので、連打は重ならない。

ピンチ・ダブルタップ等の画面固有のジェスチャーは、どの画面にも一律には付けていない（canvas は `touch-action:none`。スクロールは canvas 内の領域だけ）。

## 4. ユーザーネーム（CANVAS-Q1）

- 名前は既存のハンガー「署名」と同じもの。保存先は既存のキー `wreckline.craftSignature.v0`。新しいキーは作っていない。回路の刻印（`lastEditorName`）は、今までどおりこの署名を自動で使う。
- 保存のタイミング：開始画面で「開始」（または名前欄で Enter）を押した瞬間に 1 回。既存の `saveCraftSignatureOnce` を使う。
- 変更の制限：既存の規則のまま「一度確定したら変更できない」。確定済みのときは名前欄を出さず、名前と「確定済みです。変更できません。」を表示するだけ。確定済みの名前は、別の名前を入れても上書きされない（`saveCraftSignatureOnce` が拒否する。selftest で確認）。既存版の DOCK の署名欄も同じ関数なので、どちらの版からも二重に確定できない。
- プレイ記録との関係：このキーは、既存の設計でプレイ記録の対象外（`play-log-browser.ts` の除外。個人名を記録の書き出しに入れないため）。そのため、名前の保存はプレイ記録の件数を増やさない。「新規ゲーム（ログ記録）」でも名前は消えない（既存の動き）。消えるのはブラウザーのサイトデータを消したときだけ。
- 文字の扱い：既存の刻印と同じ `sanitizeEditorName`（前後の空白を除く、制御文字と `|` を除く、32 文字まで）。日本語入力（IME）と改行入りの貼り付けは、既存の `bindEditorNameInput` を使う。
- HTML の使用：名前欄だけが HTML の `<input>`。canvas 上の枠の位置に重ねて置き、開始した時点で `blur()` して `hidden`・`disabled` にする。以後のゲーム中は HTML の操作部品を出さない。
- 保存に失敗したときは開始しない（「名前を保存できませんでした。もう一度「開始」を押してください。」）。

## 5. DOCK（第1段階で動くもの）

- 上部 HUD：Cr・弾・装・電・箱（既存 §6 と同じ並び・色・0 は灰色・スマホ 600px 以下の短縮表示）。表示だけ（箱タップ→SORT は未移植）。
- 物資市場（購入）：弾薬・装甲パーツ・電力パーツ・ジャンク（各 6c）、未開封コンテナ（15c）。
  - 数量は canvas のボタン（−10・−1・×N・+1・+10）で選ぶ。1〜「今の Cr で買える最大」の範囲。HTML の数値欄は使わない（CANVAS-Q2）。ボタンは常に 44×44px。購入ボタンが同じ行に入らない幅では次の行に回す（2026-11-05 修正、[CANVAS_UNIFIED_V0.md §12](CANVAS_UNIFIED_V0.md)）。
  - 「購入」ボタンに「合計 Xc」。買えないときは無効で「要 Xc / 持 Yc」（既存の文言）。
  - 未開封コンテナは毎回、canvas 内の確認ダイアログ（既存 §10-6 の文言「未開封コンテナを N 個購入しますか？（Xc）」、［やめる］［購入する］）。資源の購入は確認なし（既存どおり）。
  - 購入後はページを読み直さず、その場で残高・在庫・HUD を更新し、その行に「Cr −60　弾 +10」（#300 の記号と色）を出す。
- 購入の処理（`market.ts`）：保存から最新のハブを読む → 買える数を確かめる → 既存の `applyResourceTrade` / `applyContainerBuy` → `setPlayLogOperation`（`resource.buy` {id, quantity} / `unopened.buy` {quantity}。HUD パレットと同じ名前）→ `saveHubSaveToLocalStorage` を 1 回。画面の表示が古くても、保存の値で判断するので使い過ぎない。
- 別タブ・既存版での変化は `storage` と `wreckline:hub-saved` で読み直す（読むだけ）。
- 未移植の機能は「未実装（この画面ではまだ操作できません）」の案内に文字だけで並べ、動くふりをするボタンは置かない。押せるのは「既存版の DOCK を開く」（既存版へ移動する本物のボタン）だけ。

## 8. 既知の制限（第1段階）

- 保存中・保存失敗の画面は既存の HTML（`#play-log-blocker`）のまま（CANVAS-D7）。購入のたびに、保存中の一瞬だけこの画面が前面に出る。保存失敗時の再試行・書き出しも、この HTML 画面で行う。
- 「プレイ記録」パネル（`#play-log-panel`）は canvas 版で隠している（CANVAS-D5）。記録の書き出しと新規ゲームは既存版で行う。
- 既存のセーブがあり、プレイ記録が無い（途中から記録しない）状態では、既存版と同じく記録なしで動く。
- 未移植：ハンガー（機体・修理）、回路、作戦室（出撃）、SORT（開封）、売却、署名の表示、下部タブ、HUD タップのパレット、Alpha Lab 帯、出撃ガードのバナー、PC 2 列。
- キーボード操作は Escape（ダイアログを閉じる）と名前欄の Enter だけ。Tab でボタンを選ぶ操作と、スクリーンリーダー向けの読み上げは未対応。
- 名前を変えられるのは、ブラウザーのサイトデータを消したときだけ（既存の動き）。

## 9. 次の画面を追加する手順

1. `packages/<module>/src/canvas/<name>-scene.ts` に `draw(ui, frame)` を持つクラスを作る。描画は状態を読むだけにし、状態の変更は `ui.button(..., { onActivate })` の中だけで行う。
2. 位置は `layoutXxx(frame)` のような純粋関数で計算し、描画と当たり判定の両方で同じ結果を使う。selftest で、PC・スマホ縦横・小型スマホの幅で、ボタンが 44px 以上・重ならない・枠内に収まることを確かめる。
3. ボタンの id は画面内で一意で、フレームをまたいで同じ（例 `sort:board:3:4`）。
4. 保存・取引は既存の関数を呼ぶ。呼ぶ前に `playLogBlocked()` を確かめ、`setPlayLogOperation` の名前は既存版と同じにし、1 回の操作で保存は 1 回。
5. 確認が要る操作は `ui.modal()` の中に確認ダイアログを描く。モーダルの箱の中で、ボタン以外の場所には `ui.region(id + ":box", rect)` を置く（タップしても閉じない）。
6. 長い一覧は `ui.scrollArea(id, rect, 内容の高さ, draw)` に入れる。
7. `app.ts` の `SceneId` とシーン切替に追加する。別のモジュールに置くときは、そのモジュールに `canvas/index.html` と `vite.config.ts` の入口を足す。
8. `scripts/verify-canvas-dock.cjs` と同じ形で、実ブラウザーの確認（PC／スマホ縦横／DPR 1〜3、HTML 部品が見えていない、誤発火しない、再読み込みで一致、記録が重複しない）を足す。
