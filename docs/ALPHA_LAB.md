# 公開アルファ実験室（#319）

仕様源は神宮提示の [IMPLEMENTATION_ORDER](spec-questions/alpha-lab-319-order.json)。#318マージ済みmain `64d3f83d1bdaaee65d1891607bae5ce3a3f83ca5` から作業し、同コミットの公開デプロイ39764118392 PASSを確認した。今回の変更はDraftで提出し、マージ・デプロイは行わない。

## 入り方

通常HUBの「アルファ実験室」を開き、「アルファ実験室へ入る」をタップする。認証・秘密のコマンド・開発者ツールは不要。最初は既存の「NO_SHIELD_NO_CIRCUIT」でExploreの検証用出撃を準備する。実験セーブが既にあれば、その状態から続ける。通常セーブの無料配布や進行変更は行わない。

画面には「実験用の機能です。予期しない挙動が発生する場合があります。」と表示し、スクロール中も固定表示の `ALPHA_LAB · DEBUG_FIXTURE` で通常プレイと区別する。固定表示はタップを遮らない。

従来の「盾検証モードへ入る」と6プリセット、状態確認、DEBUG_FIXTURE形式の証拠出力も維持する。

## 編集

| 項目 | 操作・保存 |
| --- | --- |
| プリセット | #318の6種類を維持。既存状態を置き換える開始・初期化には確認を出す。 |
| 資金 | 現在値表示、指定額設定・加算・0・初期額への復帰。非負の安全な整数のみ。桁あふれ・NaN・Infinity・負数・小数は保存前に拒否。HUBの残高表示も更新する。 |
| 回路 | 実装済み効果の日本語名から選択。偽盤/真盤、Online/Offline、倉庫/隊長/僚機を指定して生成。既存回路の装備・解除と、実験室で生成した検証用回路の削除。 |
| 盾 | Exploreで対象機体を選び、装備・予備・地面へ生成。既存盾のHP/最大HP・所在・装備先を編集、削除。小数を保持し、現在HPは0〜最大HP、最大HPは正の有限数。HP0は破壊として除去する。 |
| 機体 | Exploreで隊長/個別の僚機を選び、現在のHP・弾薬・基礎バッテリー活動量を編集。積載・装備回路・装備盾/予備盾も確認する。IDや他機体の装備を変更しない。 |
| 状態確認 | 既存の盾ID・現在HP・最大HP・所在・作業途中表示を維持。現在値を再表示する操作もある。 |
| 現在状態の再生成 | 「現在の実験状態を保存して再読込」で、編集済みの状態をそのまま読み直す。プリセットの初期化とは区別する。 |

回路は#318の2×2検証盤の生成処理を共有化して使い、効果プールの定義から選択する。例えばshieldは偽盤、p_shieldは真盤だけに現れ、逆の組合せは内部ロジックでも拒否する。Onlineの真盤は配線済み・Perfectロック済み、偽盤は有効なBypass。Offlineは未配線で効果0。架空のOnlineフラグや未実装効果は追加していない。既存回路の効果キーは引き直さない。

装備枚数・カテゴリ・積載枠・機体上限は通常ルールを維持する。制限緩和は今回実装していない。プリセットの5段進行は既存の検証用データであり、通常進行の段位を変更しない。装備操作の弾薬返却・再装填も既存のHUB処理を使う。

盾を所在変更しても同じID・出自・生成順を保持する。直接編集は現在の戦場で所在を確認できる盾が対象で、別マス・未回収機の盾を複製したり参照だけ移す操作は拒否する。装備済みの機体への二重装備、積載超過、搭載中/大破機への装備は拒否する。設置盾の直接移動は拒否し、実際の屹立・撤去・拾得の各2秒と衝突判定を使う。実験UIからの所在編集は明示的な実験操作であり、通常ゲームの移動・拾得ルールを変更するものではない。

機体HPはその出撃中の値で、通常の帰還摩耗・HUB耐久とは別である。HP/活動量0は通常同様に残骸化する。弾薬はその機体の出撃中の上限、バッテリーは保存される基礎容量の範囲で編集する。回路の活動量倍率は通常どおりなので、HUDの有効活動量と基礎値は異なる場合がある。盾・機体の直接編集は出撃中に行い、結果/出撃前には案内を表示する。機体の購入・通常整備は実験用HUBの既存画面を使える。

入力欄のキーは移動・射撃コマンドに渡さない。実験の一時停止/再開も可能で、実験UIをタップしただけでは一時停止を解除しない。画面内で成功/失敗と変更前後を表示する。削除、HP/活動量0、所在変更、コピー、初期化には確認を出す。

## 保存隔離とコピー

#318と同じ `debug_fixture=shield` と `wreckline.DEBUG_FIXTURE.shield.v1:` の保存領域を再利用する。通常のlocalStorage/sessionStorageへ書き戻す機能はない。通常タブと実験タブは別の保存領域を使用する。

「通常セーブを実験領域へコピー」を承認すると、通常HubSaveだけを読み取り、実験領域へ一方向コピーして実験用HUBを開く。コピー元には書込可能なStorageを渡さず、読取専用のgetItemだけを使う。元の出撃チェックポイントや通常セッション値をコピーしない。コピー先の既存実験チェックポイント・プリセット状態は破棄するため確認が必要。取消時は両方を保持する。新しい版・破損・回路欠落があるデータは拒否する。

実験中の変更は保存してから実行中のWorldへ反映する。HubSaveと途中保存のどちらかの書込が失敗した場合は前の内容へ戻し、通常領域へフォールバックしない。HUBで回路を変更した場合は、明示的な変更のときだけ次のExplore読込で途中保存の回路を同期する。通常の再読込で剥離済み回路を復活させることはない。

通常HUBへ戻るには「検証モードを終了して通常HUBへ」を使う。プリセット初期化は実験領域だけを消去する。同一ブラウザープロファイルの実験領域は1組なので、複数の実験タブで同時に初期化しない。

## 証拠JSON

「ALPHA_LAB証拠JSONを出力」は `type / runId / timestamp / preset / experimentMode / gameVersion / units / circuits / shields / currentModule / saveState` を出力する。`type`はALPHA_LAB、`DEBUG_FIXTURE`はtrue。回路効果/配線/所有先、機体の現在値、盾ID/出自/生成順/HP/所在を記録する。gameVersionはビルドしたコミット（未コミット変更があれば-dirty）で、バージョン指定があるビルドではその値を使う。

生のURLクエリ・ストレージ全ダンプ・署名・GPS情報は出力しない。旧DEBUG_FIXTURE証拠もHubSave/途中保存に対象を絞り、編集者名などを除く。通常セーブをコピーした場合も、不要な署名をテスターの証拠へ混ぜない。

## テスター向け手順

1. 通常HUBの資金・機体・回路を記録する。
2. 公開入口から実験室に入り、必要ならプリセットを選ぶ。
3. 一時停止し、資金・回路・盾・機体を対象ごとに編集する。不正入力が拒否されることも確認する。
4. 再開し、通常盾防御・予備交換・剥離・隊長/僚機の屹立・移動遮断・撤去・別2秒拾得を行う。
5. 再読込・帰還・HUB・再出撃で保存された値と盾の所在を比較する。HPは通常の帰還処理に従う。
6. ALPHA_LAB証拠を出力し、物理端末かエミュレーションかを別途記録する。
7. 通常セーブのコピーを確認付きで試し、コピー元が変わらないことを確認する。
8. 実験を初期化・終了して通常HUBを開き、手順1と照合する。

## 検証と制限

全workspaceテスト・型検査・5ビルド、[既存盾デバッグテスト](../scripts/verify-shield-debug.cjs)、[追加実験室テスト](../scripts/verify-alpha-lab.cjs)を実施する。各ブラウザースクリプトはPagesと同じベースパスで作成した5ビルドを、一時的な同一オリジンHTTPサーバーから配信する。Playwright Coreは`PLAYWRIGHT_MODULE`、Chromiumは`CHROMIUM_PATH`で指定可能。

- 旧#318のテストは、追加した折り畳みセクションと混同しないよう、最上位summaryを直接指定する変更だけを行った。従来の判定は維持している。
- 自由な盤面サイズ・装備枠の上限解除・機体追加専用エディター・通常セーブへの書戻しは今回の対象外。
- ローカルViteの分割ポートは保存を共有しないため、統合検証には同一オリジンの本番プレビューを使う。
- 公開版の新機能操作・物理スマートフォンは未デプロイのためNOT_RUN。ローカル390×844 Chromiumの結果と混同しない。
