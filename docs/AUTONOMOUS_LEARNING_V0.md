## 誰が学ぶか

- 学ぶのは `kind === "wingman"` で、`OwnedMech.instanceId` がある僚機だけ。
- `instanceId` が無い僚機は、今の `decideWingman` のまま。マスは作らない。
- 隊長機は v0 では呼ばない。下の三つの回路は、v0 の選択には入れない。→ 後続（2026-11-11 実装）: 1×1 完全を装備し `instanceId` がある隊長機は、僚機と同じ選択・点数・帳簿で学ぶ（「決定済み・実装済み：三つの回路」）。
- 小隊長になるキーは、隊長機も、`instanceId` がある僚機も、その機体に小隊長回路を装備していることである（2026-10-25 神宮）。同時の数に上限はない。全員を指定できる。全員を指定しても、追加の意味は薄い。小隊長回路のサイズは 10×10 である（2026-10-26 神宮）。完全か不完全かは未定のまま残す（2026-10-26 神宮）。効果キーは未決のまま残す（2026-10-26 神宮）。本書ではこの回路を作らない。
- 機体が自律するキーは、その機体に 1×1 完全回路を装備することである（2026-10-25 神宮）。初クリアの確定発見は一度だけ。追加決定によりジャンク作成でも、firstInvadeClear記録後の通常P抽選でP1×1を複数入手できる。作成による新しい機体の自動付与はない。隊長機では、僚機への移動の命令と航空支援も残る。
- マニュアル操作を解放するキーは、1×1 不完全回路である（2026-10-25 神宮）。開くのは、隊長の移動・射撃・回収・帰還要請・撤退である。今、回路なしで使える五つの基本行動と同じ。
- 小隊長の完全自律には、専用の学習項目が要る（2026-10-25 神宮）。項目の中身は未決のまま残す（2026-10-26 神宮）。本書では作らない。`instanceId` は機体ごとの入れ物として残す。小隊長の項目は、この v0 のセルとは別に定義する。
- 命令の姿勢（`escort` `patrol` `recover` `raid`）は変えない。散開が遊撃と地点を置く処理も変えない。学習が選ぶのは、その姿勢の中の移動と、その機体だけの荷下ろしである。

## 保存

HubSave に任意フィールド `mechLearning` だけを足す。これ以外の新しいトップレベルキーは作らない。

```text
mechLearning: {
  byMech: { [instanceId]: Cell[] }
  settledSortieIds: string[]   // 最大 64。古いものから捨てる
}
```

- 古いセーブにこのフィールドが無いときは、空の帳簿として読む。壊れたセルは捨て、残りのセルは残す。
- セルは結果が書かれたときだけ作る。全組み合わせを先に並べない。
- 出撃の開始時に、HubSave のその機体のセルを world の作業用へコピーする。出撃中は作業用を増やす。
- 精算では、作業用のセルで HubSave のその機体のセルを置き換える。同じ `sortieId` が `settledSortieIds` にあるときは、二度目は置き換えない。
- world をそのまま保存する今のチェックポイントには、作業用が一緒に残る。チェックポイント用の別キーは作らない。
- 大破しても、復旧しても、キーは同じ `instanceId` のまま。経験は機体に残る。
- 機体ごとのセル数の上限は 4096。超える新しいキーは書かず、既存のセルの加算は続ける。

実行時だけに置き、HubSave のメカ定義には足さないもの:

- `learningAction` … いま選んでいる行動
- `droppedThisSortie` … この出撃でその機体が荷物を捨てた
- `learningDecisionCount` … この出撃での判断回数。0 から始まる
- `learningDecisionAt` … 直前の判断の `world.elapsed`

古いチェックポイントにこれらが無いときは、未選択、捨てていない、0、未判断として読む。

## セル

キーは次だけ。

| 軸 | v0 の値 |
|---|---|
| `ledger` | `survival` `transport` `combat` |
| `action` | `drop` `flee` `fight` `carry` `extract` `hold` |
| `subject` | `none` `normal` `container` `circuit` `wreck` |
| `distance` | `near` `mid` `far` |
| `circle` | `inside` `close` `late` |
| `hp` | `high` `low` |
| `cargo` | `holding` `dropped` `none` |

数はすべて 0 以上の整数。無いフィールドは 0。

| ledger | 増やす数 |
|---|---|
| `survival` | `tries` `survived` `died` `leftBehind` |
| `transport` | `tries` `quizSuccess` `quizFailure` `broughtHome` `abandoned` |
| `combat` | `tries` `hits` `misses` `kills` `dodged` `struck` |

点の大きさが違う結果は、同じ数に混ぜない。

`ledger` がこの三つ以外のセルは、読んでも合計に入れない。捨てもしない。中隊全体の功績は、後の仕様が新しい `ledger` を足す。今名前が付いている中身は、排除で運び終えたコンテナだけである（2026-10-25 神宮）。項目を足す余地は残す。v0 はその `ledger` を合計しない。

未経験とは、その行動が読む `survival` のセルが無い、またはその `tries` が 0 のことである。`survival` の `subject` は常に `none`。

## 段

一つの判断で、段は一つ。比べる行動は行動だけが違い、段は同じものを読む。

- 距離。敵がいるときは、その敵まで。敵が無く回収対象があるときは、その対象まで。どちらも無いときは、隊長まで。`near` はその機体の武器射程以内。`mid` は射程の外かつ視界以内。`far` は視界の外。射程と視界は、今の `rangeMul` と `visionMul` を掛けた値。
- 円。`boarding` があるときはその中心と半径。無いときは `extract` の中心と半径。`inside` は中心までの距離が半径以内（`isInsideBoarding` があるときはそれを使う）。`close` は円の外で、中心までの距離が半径 + 視界以内。`late` はそれより遠い。
- 体力。生きていて `hp / maxHp` が 0.5 より大きいときは `high`。それ以外で生きているときは `low`。死んでいる機体は判断しない。
- 荷物。`unitLoad > 0` は `holding`。積載 0 で `droppedThisSortie` なら `dropped`。どちらでもなければ `none`。

## 区分

- `container` … フィールドのコンテナ（`salvagedCount` の対象）。
- `circuit` … 運んでいる残骸のうち、既存の記録で回路が付いているもの。回路が残骸より優先する。
- `wreck` … 運んでいる残骸のうち、回路が付いていないもの。
- `normal` … 上のどれでもない敵。
- `none` … `survival` のセルだけが使う。

v0 では、戦場の敵の区分はすべて `normal` とする。敵を `circuit` や `wreck` に上げる仕組みと、部隊が持ち帰った基本報酬を平均する仕組みは、本書では作らない。「最近」の幅は直近 10 出撃。暫定のまま残す（2026-10-26 神宮）。平均は、各出撃の基本報酬 60 の合計を 10 で割った数。該当が無い出撃は 0。区分へ上げる境界は後回し（2026-10-25 神宮）。点数表にその行があるのは、後の仕様が区分を渡したときに同じ式を使うためである。

一つの判断で行動が読む区分:

- `fight` と `flee` の戦闘セルは、今見ている敵の区分。v0 では `normal`。
- `carry` の運搬セルは、向かっている対象の区分。コンテナなら `container`。残骸なら `circuit` または `wreck`。
- `drop` の運搬セルは、その機体がいま持っているいちばん高い区分。順は `circuit`、`wreck`、`container`。
- `hold` と `extract` の運搬セルは、持っていればそのいちばん高い区分。持っていなければ運搬セルは読まない。
- どの行動も `survival` は `subject = none`。

## メニュー

姿勢ごとに開く行動は次だけ。開いていない行動は選ばない。

| 姿勢 | 開く行動 |
|---|---|
| `escort` `patrol` `raid` | `hold` `fight` `flee` `drop` `extract` |
| `recover` | `hold` `carry` `fight` `flee` `drop` `extract` |

さらに、その場で閉じるもの:

- `fight` は、生きた敵をその機体が見ている、または分隊が見ているときだけ。複数いるときはいちばん近い敵。
- `carry` は、`recover` で、積載にコンテナの余地がある、回収の途中、または発見済みコンテナがあるときだけ。
- `drop` は、`unitLoad > 0` で、時間切れでないときだけ。
- `extract` は、`boarding` があるときだけ。

固定順は `drop` `flee` `fight` `carry` `extract` `hold`。

判断は、未選択のとき、直前の判断から 2 秒経ったとき、いまの行動が完了・失敗・撤回したとき、に行う。2 秒は定数で、名前は保存キーにしない。間のフレームは直前の意図を繰り返す。完了・失敗・撤回は、回収完了、回収の中断、荷下ろしの完了、見ていた敵が倒れたまたは見えなくなった、搭乗円が消えた、である。

未経験の開いている行動が一つでもあるときは、その中から一つを試す。固定順に並べ、`learningDecisionCount % 個数` の位置を選ぶ。新しい乱数は作らない。

全部に `tries` があるときは、想定がいちばん高い行動を選ぶ。同点は固定順の先。

選んだら、その行動が読むセルの `tries` を 1 増やす。セルが無ければ作ってから増やす。`learningDecisionCount` を 1 増やす。

## 選んだあとの動き

既存の quirk（`cling` `decoy` `sniper`）の距離補正は、`hold` と `fight` の中で今どおり効く。

- `hold` … その姿勢の、今の `decideWingman`。
- `fight` … 姿勢は変えず、今の遊撃が敵へ立つ距離の取り方で、その敵へ移動して、交戦距離なら撃つ。
- `flee` … 隊長への帯同位置へ移動する。撃たない。回収を続けない。
- `carry` … その姿勢の、今の回収。
- `extract` … `boarding.center` へ移動する。撃たない。回収を続けない。
- `drop` … その機体のコンテナと、運んでいる残骸だけを、その場に下ろす。盾は下ろさない。小隊全体の `purgeCargo` は使わない。新しいログ文は足さない。下ろしたら `droppedThisSortie` を立て、この判断の移動は `flee` と同じにする。

## いつ数を増やすか

小テストは、その出来事のとき、そのとき選ばれている行動のセルに 1 を足す。

- 味方の弾が敵に当たったとき `hits`。外れたとき `misses`。弾 1 発につき 1。障害物と味方への命中は足さない。味方への命中は今の `friendlyFire` のまま。撃った側の `misses` に、狙われた側の回避は足さない。
- 敵の弾が、`instanceId` のある僚機に当たったとき、その僚機の `struck` を 1。点は −1。その弾が、その僚機を狙って撃たれ、その僚機に当たらず消えたとき、その僚機の `dodged` を 1。点は +1。狙いは弾を出した瞬間の射撃対象で、弾の実行時フィールド `aimUnitId` にだけ載せる。HubSave のキーにはしない。狙いがその僚機でない弾が消えても `dodged` は足さない。味方の弾は `dodged` にも `struck` にも足さない。当たった弾は `dodged` にしない。新しい回避の動きは作らない。
- その機体が敵を倒したとき `kills`。倒した機体のセルに足す。倒した敵の区分は v0 では `normal`。
- 回収が完了したとき、その区分の `quizSuccess`。回収を中断したとき、または時間切れで届かなかったとき、`quizFailure`。同じ対象の完了と失敗を両方足さない。完了が勝つ。
- `drop` で下ろしたとき、下ろした区分ごとに `quizFailure` を 1。同じ区分をいくつ下ろしても、その判断では 1。

精算は出撃の終わりに一度。

- 円の中で生きて帰った僚機は `survived`。
- 大破した僚機は `died`。
- 円の外で生きて残った僚機は `leftBehind`。
- 円の中に、その区分をまだ積んでいたときは `broughtHome` をその区分ごとに 1。
- 出撃中にその区分を持ったことがあり、円の中に残っていないときは `abandoned` をその区分ごとに 1。最初から持っていない区分は足さない。
- 精算のセルの行動は、終わりの時点の `learningAction`。未選択なら `hold`。段は終わりの時点の段。
- 撃破の `kills` は倒した機体。持ち帰りの `broughtHome` は運んだ機体。同じ残骸で両方足してよい。受け取る機体が違うなら、それぞれの `instanceId` に足す。

小競り合いの区間そのものには点を足さない。

## 点数

| 結果 | 点 |
|---|---|
| `survived` | +100 |
| `died` | −100 |
| `leftBehind` | −80 |
| `container` の小テスト成功 / 失敗 | +1 / −1 |
| `circuit` または `wreck` の小テスト成功 / 失敗 | +4 / −2 |
| `container` を円の中にまだ積んでいた | +8 |
| `circuit` または `wreck` を円の中にまだ積んでいた | +40 |
| `normal` の命中 / 外れ | +1 / −1 |
| 敵の攻撃を回避した / 敵の攻撃が当たった | +1 / −1 |
| `normal` の撃破 | +2 |
| `circuit` または `wreck` の撃破 | +20 |

持ち帰りに失敗した `abandoned` の点は 0。撃破点は、その区分のセルの `kills` にだけ掛かる。生還 +100、死亡 −100、置き去り −80 は暫定のまま残す（2026-10-25 神宮）。通常コンテナの小テスト成功 +1、失敗 −1、回路または残骸の小テスト成功 +4、失敗 −2 は暫定のまま残す（2026-10-26 神宮）。`normal` の命中 +1、外れ −1 は暫定のまま残す（2026-10-26 神宮）。敵の攻撃を回避した +1、当たった −1 は暫定のまま残す（2026-10-26 神宮）。`normal` の撃破 +2 は暫定のまま残す（2026-10-26 神宮）。コンテナや残骸を円まで持ち帰れなかったときの点 0 は暫定のまま残す（2026-10-26 神宮）。

## 想定

分母が 0 の項は 0。

- 生還の項 … `(survived×100 + died×(−100) + leftBehind×(−80)) / (survived + died + leftBehind)`
- 運搬の小テストの項 … `(quizSuccess×成功点 + quizFailure×失敗点) / (quizSuccess + quizFailure)`
- 持ち帰りの項 … `broughtHome / (broughtHome + abandoned) × 持ち帰りの点`
- 射撃の項 … `(hits×1 + misses×(−1)) / (hits + misses)`
- 回避の項 … `(dodged×1 + struck×(−1)) / (dodged + struck)`
- 撃破の項 … `kills / tries × 撃破点`

行動の想定は、その行動が読むセルの、上の項の和である。`tries` はあるが結果の数がすべて 0 のセルは、想定 0。

この和で、捨てた側が生還の得より低いあいだは、持ったままが選ばれる。通常コンテナは持ち帰りが +8 なので、円が `late` で持ったままの生還が悪い記録になると、捨てる側が先に勝つ。回路または残骸は持ち帰りが +40 なので、その減点が生還の得を上回るあいだは、持ったままが勝つ。

v0 の敵の撃破は +2 なので、死亡の −100 が付いた戦いより、逃げる側が高くなりやすい。敵の評価値が後から `circuit` または `wreck` として渡されると、同じ式で、生還が悪くても戦い切る側が高くなり得る。その分類を渡す仕組みは本書の対象外である。

## 決定済み・実装済み：排除で運び終えたコンテナ

この節は 2026-10-24 の神宮の決定。2026-11-11 の `TASK_ASSIGNMENT` で実装した（`explore/src/game/eliminationContainers.ts`）。

実装のしかた:

- 敵が倒れたとき（`handleEnemyDeaths` でその敵を初めて処理するとき、その敵の積荷が落ちる前）に、その敵機の視界（`canSee`）にいる、まだ取られていないコンテナへ印を 1 つ足す。発見済みかどうかは問わない。
- 「運搬が完了」は回収小テストの成功と同じ瞬間（コンテナの回収が終わって積んだとき）。そのとき印の数だけ、運んだ機体の `company` 帳簿（`subject = container`、そのときの行動と段）の `eliminatedContainers` に足す。受け取るのは帳簿を持つ機体だけ（D5 = A、2026-11-11 神宮）。
- 中断は回収小テストと同じ。印の付いたコンテナの回収が、完了する前に止まったとき（中断、届かない、回収していた機体の大破、時間切れ）は、そのコンテナの印を消す。毎フレームの最後に、印の付いたコンテナの回収者が変わった、またはいなくなったかで判定する。完了が勝つ。
- 印はコンテナの実行時フィールド（`eliminationTags`・`eliminationWorkerId`）で、今のチェックポイントにそのまま残る。古いチェックポイントは印なし。新しい保存キーは作らない。

決定:

- 点は、倒した敵の視界の中に、倒した瞬間いたコンテナに付く。視界はその敵機の視界。
- そのコンテナの運搬が、倒したあと中断されずに完了したとき、運んだ機体が点を受け取る。倒した機体は、自分で運んだときだけ受け取る。
- 同じコンテナを見ていた敵の数だけ足す。上限は付けない。敵 1 機につき +1。暫定のまま残す（2026-10-26 神宮）。
- 生きている敵の視界に入っていないコンテナを運ぶ評価の方が上に残る想定だが、合計の上限では抑えない。
- これは、今の時点で中隊功績に名前を付ける唯一の項目である（2026-10-25 神宮）。中隊功績の枠は閉じない。別の項目は、名前が決まってから足す。
- 敵を倒してその残骸を持ち帰った基本報酬とは別の点である。基本報酬は、倒してその残骸を円まで持ち帰れたとき、撃破点と持ち帰り点を足した数。回路または残骸は 20 と 40 で 60。通常コンテナの持ち帰り +8 に対して、この 60 は暫定として適当（2026-10-25 神宮）。置き去りにした機体の回収には、この 60 を付けない。通常の敵には、この 60 は付かない。

## 決定済み・実装済み：敵の基本報酬を平均する幅

この節は 2026-10-25 の神宮の決定。2026-11-11 の `TASK_ASSIGNMENT` で、平均を出せる記録だけを実装した。

実装のしかた:

- 精算ごとに、その出撃の基本報酬を `mechLearning.enemyBaseRewards` に 1 件（`{ sortieId, total }`）足す。新しいものが末尾で、10 件を超えたら古いものから捨てる。同じ `sortieId` は一度だけ（`settledSortieIds` と同じ判定）。
- `total` は、離昇のときに搭乗円の中にあった敵の残骸（`recoveredEnemyUnits`。航空支援で倒して円の中に回収した残骸を含む。剥離済みは除く）の数 × 60。味方の残骸と置き去りの機体の回収は数えない。離昇しなかった出撃（撤退・失敗）は 0。
- 平均は `enemyBaseRewardAverage` で、直近 10 件の `total` の合計 ÷ 10。10 件未満でも 10 で割る（足りない分は 0）。古いセーブは記録なし＝0。
- 平均は保存するだけ。敵の区分にも点数にも使わない。戦場の敵は今までどおり全部 `normal`。新しい画面とログ文は足していない。

決定:

- 平均する利益は、回路または残骸を倒して円まで持ち帰った基本報酬 60 である。
- 「最近」は直近 10 出撃。暫定のまま残す（2026-10-26 神宮）。
- 平均は、直近 10 出撃について、各出撃で持ち帰った基本報酬 60 の合計を 10 で割った数である（2026-10-25 神宮）。該当が無い出撃は 0 として数える。
- その数で敵を `normal` 以外に分ける境界は、後回しである（2026-10-25 神宮）。

## 決定済み・実装済み：三つの回路

この節は 2026-10-25 の神宮の整理。2026-11-11 の `TASK_ASSIGNMENT` で、未実装だった「隊長機の 1×1 完全による自律」を実装した。10/12 の開き方は、下の変更点のほかは維持する。

実装のしかた:

- 隊長機が自律するのは、`instanceId` があり、真の 1×1「4」（1×1 完全）を装備しているとき（`circuitPlay.captainTrueOne`。`isAutonomousLeader`）。この隊長の帳簿は僚機と同じ `mechLearning.byMech[instanceId]` で、出撃の開始時に読み、精算で書く。選択・点数・小テスト・精算（生還・死亡・持ち帰り）は僚機と同じ。帳簿が空なら未経験の行動を固定順で試す。
- 手動との関係は D1 = A（2026-11-11 神宮）。入力が無いフレームだけ学習で判断し、動く。入力があるフレームは今の手動の操縦のまま、判断もしない。
- 僚機への移動の命令（`wing_mobility`）と航空支援は今のまま残る。
- 隊長のメニューと動きは D4 = A（2026-11-11 神宮）。
- 1×1 不完全による五つの基本操作のゲートは掛けない（D2 = B、2026-11-11 神宮）。五つは回路なしで使える。D3 は D2 = B のため使わない。
- 僚機の 1×1 不完全の `release` 時の 2 倍（攻撃力・射程・視界）は既存のまま残る。隊長機には付かない（テストで固定）。
- 1×1 完全の入手経路（初クリアの確定発見は一度だけ、ジャンク作成・通常の P 抽選）と、作成による自動付与なしは変えていない。小隊長回路は作っていない。

整理:偽の 1×1 はコマンドを開かない。真の「4」を隊長に付けると `wing_mobility` と航空支援が開く。僚機に付けると、その僚機が自律する。

- 1×1 不完全回路は、マニュアル操作を解放する。開くのは、隊長の移動・射撃・回収・帰還要請・撤退である（2026-10-25 神宮）。今、回路なしで使える五つの基本行動と同じ。
- 僚機に付けた 1×1 不完全は、`release` のとき攻撃力・射程・視界の 2 倍を残す（2026-10-25 神宮）。隊長機には、この 2 倍は付かない。
- 1×1 完全回路は、装備した機体を自律させる。初クリアの確定発見は一度だけ。追加決定によりジャンク作成でも、firstInvadeClear記録後の通常P抽選でP1×1を複数入手できる。作成による新しい機体の自動付与はない。
- 小隊長の指定は、サイズ 10×10（2026-10-26 神宮）で、完全か不完全かは未定のまま残す（2026-10-26 神宮）小隊長回路を、その機体に装備していることである。効果キーは未決のまま残す（2026-10-26 神宮）。隊長機も、`instanceId` がある僚機も、同じキーである。
- 1×1 完全を隊長機に付けたとき、今開いている僚機への移動の命令（`wing_mobility`）と航空支援は残す（2026-10-25 神宮）。そのうえに、装備した隊長機の自律が乗る。

- **隊長が小隊長のとき**: 生きているあいだ、移動・クリック移動・射撃・回収の手動入力は効かない。4 つの方針（キー 1〜4、canvas と既存版の「小隊方針」と僚機カードのボタン）が操作になり、`release` でも出せる。帰還要請・撤退・航空支援は今のまま。大破しても指揮は続く。小隊長でないあいだは、1×1 完全による隊長の自律（入力があるときは手動）のまま。
- **記録**: 隊長が小隊長として出した任務（プレイヤーが出したもの、E1 で自分で出したもの）は、受けた僚機 1 機ごとに、その任務の `tries` を 1。遊撃を受けた僚機の撃破は `raid / normal` の `kills`。精算は出撃の終わりに一度で、受けた僚機ごとに、最後に受けた任務の生還・死亡・置き去り（E3）。回収の任務なら、受けてから持った区分の持ち帰り・放棄。個体の帳簿（v0）はそのまま別に増える。
- **想定**（`commandExpectation`）: 生還の項 ＋（回収）区分ごとの `broughtHome / (broughtHome + abandoned) × 持ち帰りの点` ＋（遊撃）`kills / tries × 2`。分母 0 の項は 0。未経験（`tries = 0`）の任務を固定順（帯同・哨戒・回収・遊撃）で先に試し（判断回数で回す）、全部あれば想定がいちばん高い任務。同点は固定順の先（`chooseCommandStance`）。
- **僚機が小隊長のとき**: 指定と入れ物はあるが、自分で任務は出さない（分担が決まるまで。対象外）。
