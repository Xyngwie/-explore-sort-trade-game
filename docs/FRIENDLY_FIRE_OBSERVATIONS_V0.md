# 誤射の学習用観測 v0

神宮の2026-10-17の決定：誤射の回数だけをバックグラウンドで数え、精算後も学習材料として保存する。結果画面の回数表示・報酬ペナルティはない。ML学習そのものは将来の作業。

- 出撃中と結果の既存チェックポイントに、任意フィールド `friendlyFire: { count, byShooter }` を持つ。countは味方の弾が味方に命中した回数。散弾は当たった弾ごとに1回。敵どうしの攻撃、障害物・回避・外れは含めない。
- byShooterは味方射手の `OwnedMech.instanceId` 別の命中回数。ID未設定の開発出撃だけunit.idを使う。個体ごとの学習に使えるよう、合計だけでなく射手の集計も残す。
- 精算画面を描く際に、localStorageの `estg.explore.friendly-fire-history.v1` へ `{ version: 1, battles: [{ sortieId, count, byShooter }] }` として保存。既存の帰還sortieIdで重複を防ぎ、再表示・リロードで加算しない。0回の戦闘も記録する。既存データは自動削除しない。
- HUBセーブ、クレジット、報酬、URLハンドオフは変更しない。別のlocalStorageキーなのでHUBセーブのエクスポートには含まれず、同じブラウザー内のローカル記録である。
- 保存拒否・容量不足・未知版・破損データは上書きせず、精算を妨げない。結果の再描画時に再試行できる。保存できるまでは途中保存のカウンターが残るが、ブラウザーの保存領域自体が使えない場合の永続化は保証できない。
- 旧チェックポイントはフィールド省略を0回・空の射手集計として読み込む。旧弾の形式は変更しない。瞬間的な「誤射」表示はWeakMapで、再開時に再生しない。
