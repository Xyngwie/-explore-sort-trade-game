## 1. 世界観

- 主人公は何も持たない最下層スカベンジャー。機体は全機同じ。隊長機だけパイロットが乗っていて、手動操作で基本行動（歩く・撃つ・拾う・帰還）ができる。
- 僚機は隊長機からの接続で動く。回路は無人機が自分で動くための頭で、回路なしの僚機は帯同するが棒立ちで自衛のみ（#139 と一致）。

## 2. 回路

- 回路は1種類で、効果はいろいろ。既存のステータスアップ型もその1つ。ほかにコマンド解放の効果がある。
- コモンは、メイン効果に加えて装着した機体の回路枠を +1〜2 する（ドミニオンのアクション権のイメージ）。レアを積むには枠を広げるコモンが要るので、終盤でもコモンに価値がある。
- 機体の基本枠は全機1（隊長機も同じ）。
- 部隊全体で持てる回路の総数に上限がある。1機に集中させても分散させてもいい。
  - **追加決定（旧 §8.2-9）:** 部隊の回路上限は **装着中の数だけ** を数える。未装着の回路は無制限に持てる。
- ~~入手はジャンクからの作成か、お金での購入。~~
  - ~~**追加決定（旧 §8.2-6）:** 入手は **ジャンクからの作成**、**お金での購入**、**Restore**（回路の入手先として残す）の3つ。~~（旧 §8.3-4 で置き換え）
  - **追加決定（旧 §8.3-4）:** 回路の入手先は4つ。(1) ジャンクから作る（HUB）(2) お金で買う（HUB）(3) 敵がドロップ（Explore）(4) 戦場で拾う（Explore）。**Restore は入手先ではない**（§2.1）。
- 付け替えは HUB でのみ、無料。出撃中は不可。
- **追加決定（旧 §8.2-1）:** 隊長のコマンド（キャンプ等）は引き続き回路で解放する。判定は **隊長機に装着した回路**。僚機の方針は **その僚機に装着した回路** で判定する。「装備回路は出撃単位で共有」の前提は機体ごとに変える（背負い時の合算は §6 のとおり）。
  - **追加決定（旧 §8.3-3）:** 小隊方針（キー1〜4）は **解放済みの僚機にだけ** かかる。未解放の僚機は今の状態のまま（回路なしなら自衛のみ）。ログかカードで「○○は未解放のため対象外」と分かるようにする。全員未解放なら従来どおりロック。
- **追加決定（旧 §8.2-7）:** 今の「所持しているだけで効く」回路ボーナスは **装着制** に移す。`maxCircuits = 8` と古いものからの自動削除は廃止する。

### 2.1 Restore と回路のサイズ（追加決定・旧 §8.3-4）

- Restore は、手に入れた回路の効果を発揮させるための作業モジュール。**どの回路も Restore を通すまで効果が出ない**。
  - **追加決定（旧 §8.4-2）:** 効果が出るのは成果が **Fully Awakened** と **Bypass** のとき。どちらも効果は満たした数字の合計（下の評価値）。**Offline は効果なし**。
  - **追加決定（旧 §8.5-4）:** **ループなしで Bypass した回路は評価値 0 で効果なし**（確定）。そのかわり、Bypass を確定する前に評価値が分かる表示を入れる（ループなしなら「効果 0」と分かるように）。STATUS 項目12（Restore）に含める。現行 UI との差は §9.2 C21。
    - **追加決定（旧 §8.5-4 の補足）:** 「Bypass を確定する」の案内に **評価値を出す**。ループがないときは **「効果0になる」と明示** する。ボタンは押せるままでよい（ループなしの Bypass は禁止しない）。→ **実装済み**（STATUS 項目12、§9.2 C21）。
- (1) ジャンクから作った回路は **まっさらな白回路**。(2)(3)(4) は **中古** で、ランダムにエッジや×マークが最初から入っていることがある。その跡は正解とは限らず、消したり書き直したりできる。
- ジャンクから作れる回路のサイズは、**過去にパーフェクトで Restore できた最大サイズ＋1**。最初（パーフェクト未達成）は **2×2** から。拾った・買った回路はこの上限より大きくてもよく、それをパーフェクトで直すのが上限を上げる手段になる。
  - **追加決定（旧 §8.4-4）:** 作成サイズは **2×2 から「最大＋1」までの好きなサイズ** を選べる。
  - **追加決定（旧 §8.4-2）:** 作成サイズの上限が上がるのは **Fully Awakened（パーフェクト）** のときだけ。Bypass では上がらない。
  - **追加決定（旧 §8.5-5）:** 作成サイズは **正方形（N×N）だけ**。長方形は作れない。
  - **追加決定:** 現行のジャンク作成は 4×4 固定（§9.2 C10）。STATUS 項目14の実装で 2×2 始まりに合わせる。作成コストは §2.2。
  - **追加決定（旧 §8.4-6）:** パーフェクト盤の注入を **要求サイズで作れる** ようにする（現行は 2×2 しか出ない、§9.2 C17）。STATUS 項目12（盤面サイズ可変化）に含める。→ **実装済み**（STATUS 項目12、§9.2 C17）。
- **サイズと効果の強さ（決定）:** 回路の評価値は、盤面で満たした数字の合計。したがって盤面が大きいほど評価値の上限も自然に上がる。
  - 根拠（現行実装）: `packages/restore/src/circuit.selftest.ts` L173 `assert.equal(full.effect.effect, 8); // four satisfied 2s`（2×2 の検証用真盤で、満たした 2 が 4 つ → 評価値 8）。計算は `packages/shared/src/circuit-effect.ts` の `computeCircuitEffectValue`。
  - **追加決定（旧 §8.4-1）:** 評価値の細則は **現行実装をそのまま採用** する（`RESTORE_V0.md` §5.6）。閉ループ必須（ループなしは 0）、複数ループなら最小の1本だけを数える、数字 0 はパーフェクトのときだけ各 4 として加算。
  - 評価値をステータスアップ量・コマンド解放にどう換算するかは **未決**（回路とコマンドの対応表と一緒に決める。§8.1、旧 §8.5-3）。
- 用語: 本書の「評価値」は、コード・既存文書（`RESTORE_V0.md` §5.6、`TRADE_HANGAR_V0.md` §3.4b、Restore の画面）の「効果値」（`effect`）と同じもの。

### 2.2 回路の作成コストと売値（追加決定・旧 §8.5）

- **追加決定（旧 §8.5-1）:** ジャンクから回路を作るコストは、サイズ N×N で **ジャンク 2N 個 ＋ 2^N クレジット**（価格の変更として承認済み）。

  | サイズ | ジャンク | クレジット |
  |---|---|---|
  | 2×2 | 4 個 | 4c |
  | 3×3 | 6 個 | 8c |
  | 4×4 | 8 個 | 16c |
  | 5×5 | 10 個 | 32c |
  | 6×6 | 12 個 | 64c |

  - 現行の実装（#133 `packages/trade/src/junk-circuit-craft-ui.ts`）との差: 現行は **ジャンク 4 個・クレジット 0 で常に 4×4**（`JUNK_COST = 4`、`createEmptyCircuitBoard(4, 4, …)`）。新しいコストでは 4×4 はジャンク 8 個＋16c、ジャンク 4 個で作れるのは 2×2（＋4c）。実装は STATUS 項目14（コードの値は本書では変えない）。§9.2 C10。
- ~~**追加決定（旧 §8.5-2）:** 回路の売値は **現行どおり 30c ＋ 評価値 × 3c**（変更なし）。~~（下の改定で置き換え）
- **追加決定（旧 §8.5-2 の改定、2026-09-28・価格の変更として承認済み）:** 回路の売値は **25c ＋ 評価値 × 3c**。最低額を 30c から 25c に下げる（評価値1あたりの 3c は変えない）。**Restore していない回路も今までどおり売れる**（評価値0なら 25c）。
  - 実装: `packages/trade/src/circuit-sell-prices.ts` の `CIRCUIT_SELL_BASE_CREDITS = 25`・`CIRCUIT_SELL_CREDITS_PER_EFFECT = 3`・`circuitSellPriceCredits(effect) = 25 + floor(effect) × 3`。売却処理は `packages/trade/src/hangar.ts` の `sellCircuit`（盤から `computeCircuitEffectForBoard` で評価値を出して価格を決める。成果状態は見ない）。文書は `TRADE_HANGAR_V0.md` §3.4b。定数は `hangar.selftest.ts` で 25 / 3 を検証している。
  - 小さい回路を作って売る **薄利多売の稼ぎ方は意図して許す**。
  - 新コストの 2×2 の収支（ジャンクを買値 6c で買った場合、4個 24c＋4c＝**28c**）: そのまま（評価値0）売ると 25c で **−3c の赤字**。Restore して評価値1なら 28c で **収支0**、評価値2以上で **黒字**（評価値 k なら +3(k−1)c）。Sort で集めたジャンク（売値 5c）を使うなら 20c＋4c＝24c 相当で、評価値0でも +1c。
  - 項目14が入るまでは今の「ジャンク4個・0c で 4×4」（§9.2 C10）が残るので、ジャンクを 6c で4個（24c）買って作り、そのまま 25c で売る **+1c の循環** が残る。これは **許容する**（項目14で 2×2＝28c になれば −3c になり消える）。
- 回路をお金で買うときの値段は未決（§8.1）。

## 3. 段位とプログレッション（ディアブロ3のグレーターリフト型）

- Invade（マインスイーパー）をクリアすると段が上がり、部隊の回路上限が増え、Explore の難易度も上がる。持ち物は全部持ち越す（リセットなし）。
- Invade の途中で「この盤面を諦めて撤退」できる。撤退すると一段下がり、必要ならさらに下がれる。部隊上限と獲得資源は維持。
- 最大到達を伸ばすプッシュ用のビルド（集中型）と、低い段を快適に回すファーム用のビルド（分散型）が両立する。ファーム用のビルドだけではプッシュできないようにする。

## 4. 開始状態

- 僚機0、回路上限0、1機目の機体はコスト0（負けてもノーリスク）。
- 狙いのバランス：素の機体で敵2体までは順番に倒せる。3体目には負ける（引き撃ちや回避がうまければ倒せる）。2体同時に会敵すると負ける。
- 最初の目標は、コンテナを1〜2個持ち帰って Invade をクリアすること。初回クリアの報酬はお金で、僚機か回路のどちらかがようやく1つ買える額にする。

### 4.1 機体数と出撃コスト（追加決定・旧 §8.2-2）

- 機体数の上限3は当面維持する。将来は撤廃する予定（20機出撃など）。
- 出撃で機体ごとに電力パーツを消費させ、稼ぎとの兼ね合いで機数を判断させる。
- 現在の実装の出撃コストは §9.2 C12 を参照（出撃時に消費するものはない）。

## 5. 喪失と救済（ウィザードリィ並みに淡泊）

- 戦場から持ち帰れないものは持ち帰れない。
- 大破した機体は積載2で背負って帰れば、機体も回路も戻る。
  - **追加決定（旧 §8.2-3）:** 背負って持ち帰った大破機の修理は **有料**。装甲パーツ＋電力パーツ＋修理費クレジット。新品購入より安くする（金額は §8.1）。
- 背負えなければ機体は失う。回路はやられた場所に確定で落ちて、出撃をまたいで残る。Invade の盤面に「どのマスで何を落としたか」を記録する。
- 落ちた回路は所有権を失っているので、部隊上限から外れる（代わりを買って強いマスへ取り返しに行ける）。~~回収して上限を超えたら、HUB でどれを捨てるか選ばせる。~~（旧 §8.2-9 により削除: 上限は装着中の数だけを数え、未装着は無制限に持てるため）
  - **追加決定（旧 §8.4-3）:** 回収した自分の落とし物の回路は **元の状態のまま戻す**（中古扱いにしない）。
- 帰還時に搭乗円の外にいた僚機は置き去り（#139/#141 の既存ルール）。
  - **追加決定（旧 §8.2-4）:** 置き去りの僚機は「背負われなかった大破機」と同じ扱い。機体は失い、回路はその場所に確定で落ちて残る。

## 6. 背負い

- 機体を背負うと、背負われた機体の回路がステータスアップも含めて全部、背負った側に合算される。移動速度が落ちることが十分なデメリット。
- 大破していない機体も背負える。例：プッシュ時に強い味方を背負って戦い、背負っている側が大破したら、降りた強い機体が戦う。
- 僚機が隊長機を背負うと、プレイヤーの手動操作になる。

## 7. 隊長機の大破

- 大破しても即作戦失敗にはしない。大破した時点で撤退ボタンを必ず出す。
- 背負える僚機がいれば、その僚機を手動で操作して帰還できる。
- 撤退を選ぶと、パイロットは命からがら逃げて救助される。救助費用として所持金の半分を取られる（ドラクエのルール）。積荷とその場の機体は失い、回路はやられた場所に確定で落ちる。
- **追加決定（旧 §8.2-5）:** 隊長が無事なときの引き上げは **通常の帰還プロトコル（抽出要請）だけ**。既存の「撤退」ボタン（`abortSortie`）は転用する。隊長が無事なうちは **無効**、隊長機が大破したときだけ有効になり、救助撤退（所持金の半分、積荷とその場の機体は失う、回路はその場に落ちる）を呼ぶ。
- **追加決定（旧 §8.2-8）:** 出撃中にブラウザの「戻る」を押したら確認を出す。選択肢は「**戦線復帰**」（戻るのを止めて出撃を続ける）と「**撤退**」。撤退したら救助撤退と同じ扱い。全機大破扱いはやめる。
  - **追加決定（旧 §8.3-1）:** 「戻る」の確認で「撤退」を選ぶと、**隊長が無事でも救助撤退扱い**。出撃を投げ出す操作への罰。追加決定（旧 §8.2-5：撤退ボタンは隊長機大破時のみ有効）の **例外** とする。
  - **追加決定（旧 §8.3-2）:** Invade の **強制戦闘ロック中**（Explore へ移る前）の「戻る」も同じ確認（戦線復帰／撤退）を出す。撤退なら救助撤退。全機大破扱いはやめる。
