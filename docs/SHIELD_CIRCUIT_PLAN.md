## 実装

- 偽盤効果キーの末尾へ `shield`（「盾」）を追加する。偽盤20候補、真盤18候補。購入・Sort・Restoreの既存の正規化/効果抽選経路を共用し、保存済みの有効キーは変更しない。
- 盾回路は同じ機体に1枚まで。既存のカテゴリ制限に盾カテゴリを追加し、装備操作・出撃検査・敵生成の双方へ適用する。武器/特殊弾とは別カテゴリ。盾本体の容量や重量は変更しない。
- 「残骸盾」は実際に作業する隊長機自身の盾回路装備があるときだけ表示し、ロジックでも開始を拒否する。搭載機の回路では開放しない。既存の回路分類と同じく有効回路を参照する。
- 剥離開始時に元機体（敵・味方残骸・置き去り残骸）の盾回路効力を取得し、`50 + effect`を進捗へ固定する。12.75なら62.75。作業機体の値は使わない。8秒・静止・中断条件は変更しない。
- 新しい進捗はチェックポイントと同じ盤面/マスの保存へ`shieldMaxHp`を持ち、再開・完成後・拾得時に再計算しない。生成時HP＝最大HP。既存個体のID/HP/出自/生成順は維持する。
- v2.1により旧開発セーブ移行・旧進捗再開は保証しない。利用可能な旧進捗で新しいフィールドがない場合は50で完了する（K4=A）。新仕様の途中保存・再開と#312/#313の帰還/置き去り/交換/盤面再生成は維持する。
- 地面盾の回収・装備・防御・予備保持・交換には盾回路を要求しない。
- 敵の偽盤候補に追加し、最高効力が盾なら既存の待ち伏せ。最高値同点は既存の先に生成された回路を優先。新しい盾の生成・回収・装備AIは加えない。

P盾回路と「屹立」は後続。元JSONのバリケード案は承認済み実装範囲ではない。

## 検証

`shieldCircuit.selftest.ts`は候補/真偽・保存キー不変・装備/出撃制限・作業者/搭載機区別・元機体の端数効力・チェックポイント/マス精算後再開・無回路での拾得/防御・味方/置き去り元回路・敵候補/行動/同点を検証する。

既存の剥離・マス保存テストには、作業機体の盾回路を明示的に装備する。対象残骸の回路や時間・再取得防止の期待は弱めない。`hub-save-v3.selftest.ts`のキー未保存の`ha`は、候補数19→20で新規抽選値がfast_round→recoverへ変わるため期待値を更新。保存済みキー不変のテストは維持する。効果候補数は19→20、recoverの既存位置18は不変。

実操作スクリプト（Playwright + Chromium、390×844）は次を使う。

- `verify-shield-circuit.cjs`：無回路でコマンド非表示、地面タップ/一覧/2秒拾得、正確な個体保存、HUBの表示/説明/重複装備拒否。
- `SHIELD_SOURCE_EFFECT=12.75 verify-wreck-stripping.cjs`：実射撃による敵破壊→8秒剥離（途中再読込）→耐久62.75→2秒拾得→15秒帰還→再取得しない精算/結果再読込。対照の未剥離残骸は受領。
- `verify-field-persistence.cjs`：通常帰還/再出撃/残り時間剥離、地面盾の正確なHP/ID、共有HQ、保存拒否、実Invade盤面再生成。
- `verify-shield-return.cjs`：通常/救助/生存時間切れ/大破時間切れ/帰還失敗、交換途中の凍結再開と置き去り盾、盤面再生成。
