# 球体機体・運搬・自律学習AI 設定資料（設計案）

更新日: 2026-10-17
状態: 世界観・設計の議論を記録。確定事項と検討案を区別する。**実装済みを意味しない**。

## 1. 世界観と設計思想

機体は人型兵器ではなく、掲示板コミュニティの生活を支える大量輸送と戦闘を両立する大型球体機械である。戦闘で勝利するだけでなく、食料・医薬品・生活物資・資材を持ち帰ることが遠征の目的となる。

機体の運動機構は人間の身体を模倣する必要がない。二足歩行技術が不可能な世界ではなく、基本運動制御を単純化して、AIに「どう戦い、どう運ぶか」を学習させるという技術選択がある。

> 機械に人間の歩き方を教える必要はない。機械には、戦い方と運び方を学ばせればよい。

この文は設計思想の表現であり、ゲーム内の正式な台詞ではない。

### 1.1 色分けの文化（2026-10-17 神宮の設定・確定）

言葉や設計図が失われた世界でも、色分けの文化（赤＝危険・減る、緑＝増える・安全など）は記号として残っている。

ゲームの画面で決めた次の色は、この設定に沿っている。

- 陣営: 青＝指揮下、緑＝友軍、黄色＝中立、赤＝敵対（[EXPLORE_FACING_AIM_V0.md §9](EXPLORE_FACING_AIM_V0.md)）
- 資源: 弾薬＝赤、電力＝黄色、装甲（防御）＝青（[SORT_V2_RULES.md §4.3.1](SORT_V2_RULES.md)）
- 増減: 増える＝緑、減る＝赤、どちらでもない＝灰色（Trade の資源履歴）

## 2. 球体機体の寸法と内部構造

- **直径15m：現在の有力候補**。当初のイメージは直径30m。外部コンテナ搭載を前提に15m程度への小型化を検討しており、最終寸法は未確定。
- コックピットは球体のほぼ中心に位置する。強固に保護され、隊長機は大破後もコックピットが壊れず指揮を継続できる。
- 内部は機器で隙間なく埋まっているのではなく、空洞も多い構造。
- 武器ユニットと機動ユニットは、質量・機体バランスを考慮して配置する。
- 球体外殻がそのまま地面を転がる方式ではなく、**外殻内側に2本の無限軌道を配置し、接地部だけを下方に少し露出させる**案を検討する。
- 既定の全方向移動（横移動を含む）との整合のため、履帯ユニット自体を旋回台座に載せ、機体正面と走行方向を独立させる案が有力。ただし構造・切替時間は未確定。
- 球体外殻・内部空洞・中心コックピットの組み合わせは、防護・整備・積載・旋回制御に関係する。空洞だけで防護性能が保証されるわけではない。

## 3. 貨物とコンテナ

- 世界的に流通するISO海上コンテナを物資輸送の基準として検討する。
- **20ft ISOコンテナ**は外寸がおおむね長さ6.06m × 幅2.44m × 高さ2.59m、標準型の内容積約33m³。2基で約66m³。
- **1機あたりコンテナ2基の運搬**を想定。初期案は球体内部への収納だったが、上部・外部搭載により本体を小型化する案が浮上した。
- 上部左右への搭載、積み下ろし機構、満載時の重心・電力消費・機動性は未決定。
- **コンテナ2基の輸送と、味方機体の回収・運搬は別の寸法・搭載条件**として扱う。既存の機体輸送実装をこの資料だけで変更しない。

## 4. 機体の向き・視界・射撃

確定した設計方針:
- 機体は全方向へ移動でき、正面と移動方向は独立する。
- 通常は移動方向へ向き、交戦対象がある場合は敵方向への旋回を優先する。
- 近距離は正面中心**270°の周辺視界**、長距離は正面中心**60°の前方視界**。それぞれの距離は未決定。
- 味方が視認した敵の正確な現在位置は、部隊内でリアルタイム共有する。共有敵への旋回は攻撃見込みによる条件付き自動旋回。
- **正面3°の精密な射撃方向**を使い、味方の射線干渉を確認する。実際の誤射判定には味方の機体半径・弾道・距離も必要。
- 誤射判定は**リスク判断型**。危険を認識していても戦術的に射撃する場合があり、結果から学習する。
- 旋回には有限の速度があり、機体性能や回路による違いを設ける方向。具体値は未決定。
- 射線を遮る障害物を扱う。視界遮蔽と弾道遮蔽の詳細は未決定。

## 5. 個体ごとの戦闘・運搬学習

- 経験は**OwnedMech の instanceId に紐づく個体固有の永続データ**。帰還・再出撃を跨ぎ、大破しても機体側に残る。残骸から機体を復旧すれば経験を引き継ぐ。
- 命中・外れ・障害物への着弾・味方への誤射を区別し、状況別の射撃判断を学ぶ。
- 横移動、後退、停止、遮蔽物、盾、瞬間移動などの防御手段を、攻撃特性と電力コストから選択する。例: 瞬間移動の電力5は説明用の仮定であり確定コストではない。
- 敵弾の位置・速度・進行方向を認識して回避し、経験が増えると敵の挙動から発射前の予測も試みる。予測は外れ得る。
- 戦闘時は自律移動を行う。ただしプレイヤーの明示的な移動指示、運搬・回収などの任務を優先する。
- 運搬では経路、積載、電力管理、回収順序、危険回避、護衛との連携、撤退判断を経験から学ぶ。
- 回路により実行した有利な戦術を自機が学習できる。回路を外しても**戦術的な知見**は残るが、回路固有の物理能力は残らない。
- 味方の行動を観察して戦術を学ぶ。ただし経験値・学習データの丸ごと共有はせず、自機が利用可能な行動だけを試して学ぶ。
- 学習には単一の正解を強制しない。偏った行動傾向も、特定の状況では有効となり得る。指揮官がその個性を見極めて編成・任務を与える。
- 学習の v0 は [`AUTONOMOUS_LEARNING_V0.md`](AUTONOMOUS_LEARNING_V0.md) が正式仕様である。本書のこの節と食い違うときは、その正式仕様を優先する。予測回避、瞬間移動、遮蔽、中隊功績、敵評価の平均は、v0 の対象外のままである。

## 6. 小隊から中隊への指揮の変化

- ゲーム進行により、隊長機の手動操作を手放す代わりに、小隊の機体数上限を撤廃し、中隊規模の指揮へ移行する構想。
- 手動操作の隊長機が完全自律すると、その同じ機体の役割は自立する小隊長になる（2026-10-25 神宮）。別の小隊長に指定できるのは、`instanceId` がある僚機である。指定の操作、同時の機数、完全自律の学習項目は未決。学習の正本は [`AUTONOMOUS_LEARNING_V0.md`](AUTONOMOUS_LEARNING_V0.md)。
- 隊長機は戦闘性能の特別な強化機ではなく、帰還コマンド・航空支援の権限を持つ機体。
- 中隊運用では、隊長機を指揮通信のアンテナとして戦場に配置する必要がある。
- 隊長機が大破しても、強固に保護されたコックピットと通信機能が残り、**小隊・中隊への指揮は継続可能**。帰還・航空支援の大破時の個別条件は既存契約を優先し、未確認事項を勝手に確定しない。
- 部隊への任務目標の指示と、個体AIの戦術的な裁量を組み合わせる。細かな命令体系、通信距離・妨害、隊長機回収時の通信条件は未決定。
