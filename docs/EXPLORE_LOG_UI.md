## 仕様と実装

| 設問 | 挙動 |
| --- | --- |
| Q125–128の表示接続 | HubSaveの修復履歴を赤色のログ項目として表示。保存のUTC時刻を端末のローカル時刻に整形。既存の戦報の赤を再利用 |
| Q129–131 | 修復ログをタップすると、UTC時刻・種別・対象・変更前後を含む全文をClipboard APIで1回コピー。成功は「修復詳細をコピーしました」、失敗は「コピーに失敗しました」の短い非ブロッキング通知のみ。自動再試行・モーダル・戦闘ログ追加なし |
| Q132 | 通常タップはコピー。長押し・範囲変更はブラウザー標準の文字選択を利用。native selectionchange/contextmenuを伴うジェスチャーの解除クリックはコピーしない |
| Q133–137 | 選択中の最初のタップは、同じログ・別ログ・通常ログ・他のゲームUIでも選択解除だけ。戦場での最初のドラッグは全体を消費し、背後のpointerdown/move/up/clickをゲームへ渡さない。既存の機体行動・入力状態は変更しない |
| Q138–140 | ログ内の範囲選択やスクロールは標準動作を維持。選択元がパネル外へスクロールしても行DOMを削除しない |
| Q141–142 | 選択中の新規ログも蓄積。閲覧位置を保持し、選択解除だけでは自動追従を再開しない |
| Q143–145 | 最も新しい行が実際にパネル内へ見えたときに追従再開。scrollHeightとの差の閾値では判定しない。上方向の閲覧スクロールで追従を停止。再開通知なし |
| Q146–150 | 追従停止中の新着件数を下部ボタンに表示。1〜999は実数、1000以上は999+件、内部件数は保持。0件は非表示。タップで瞬時に最新へ移動し未読を消去。選択中の初回タップは解除だけ |
| Q151–155 | 行キーと行内オフセットをアンカーとしてサイズ変更前の閲覧箇所を維持。連続変更中も元のアンカーを使い、変更が100ms途絶えたところで復元。変更中の新着と未読計数も継続 |
| Q156–160 | 待機中の手動スクロール・選択範囲変更・選択解除は予約復元を取り消す。次のサイズ変更は新しい閲覧位置を基準とする。未読ボタンなら復元予約を取り消して即座に最新へ移動 |
| Q161 | 追従中のサイズ変更と新規ログが重なっても最新を即表示し、安定後も最新を維持 |

## 実装上の契約

- 表示は古い行→新しい行の順で、新しい行は下へ追加する。旧UIの「新しい18件をHTMLで置換」を廃止する。
- ログ専用DOMをHUD更新から分離し、既存行を毎回作り直さない。UI全体の再描画でも同じパネルを再使用する。文字選択中に全体再描画が必要になった場合は、選択解除まで描画だけを保留し、シミュレーションは止めない。
- 修復履歴は既存のHubSave読込時に表示用へ整形してキャッシュし、毎HUDフレームでlocalStorageを読まない。別タブのHubSave更新はstorageイベントで再取得する。
- 戦闘ログの保存上限（maxTacticalLog + maxBattleReports）は変更しない。pushLogの到着フィードで、保存上限を超える一括追加もUIへ欠落なく渡す。パネルは開いている出撃中に受け取った行を保持するため、選択元や閲覧中の行は保存上限による切り詰めで消えない。
- 画面再読込時は既存checkpointの保存範囲と永続修復履歴から再開する。UIの未読数・閲覧アンカーの再起動越し保存は今回追加しない。
- 閲覧アンカーの探索は二分探索。1000行を超えても毎HUD更新で全行の座標測定をしない。
- Pointerの4 CSS pxはタップとドラッグを区別する実装上の許容値。ゲームの移動・射程の距離ではない。長押し時間の独自タイマーは設けず、標準の選択・contextmenuを維持する。
- ResizeObserverによる復元を、レイアウト自身が起こしたscrollTopの補正で取り消さない。待機中にユーザーのwheel/pointer/keyboardスクロールがあった場合は取り消す。
- 修復ログのSpace/Enter操作や未読ボタンのキーボード操作はゲームの射撃入力へ流さない。
