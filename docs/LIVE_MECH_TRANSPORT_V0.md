# 生存機体の積載・独立射撃・移動電力

2026-10-14、神宮の回答D・Q2 A・Q3・Q4・Q5 Aに基づく。従来の残骸積載と段位／装備カテゴリ#289を引き継ぐ。

## 積載と戦闘

- 生存機体1機は積載2（コンテナ2個分）。既存の積載速度表120／75／60／45／30／15／0を使う。能力倍率・回路の移動補正も既存どおり。
- 僚機のカード／地図上の機体から「積載」を選び、隊長が回収半径内で8秒かけて積む。必要な回路はない。搭載中の僚機には「降ろす」。回収回路のある僚機も既存の「回収」対象として生存機体を選べる。積載中の機体は別の機体を積めない。
- 対象機体は積載作業中に移動せず、射撃は継続できる。運ぶ側が回収半径から離れると作業中断。
- 生存搭載機は運ぶ側と同じ位置で、自身の正面3°・旋回90°/秒で狙う。狙う敵がいない間は最後の向きを保ち、運ぶ側の向きや搭載前の移動方向には合わせない。運ぶ側の積載減速も受けない。自身の武器種・特殊弾・弾薬・射撃間隔を使って戦う。武器は合算・変換しない。MMRの運搬機＋LMGの搭載機は2本が同時に働く。1機ごとのカテゴリ制限は維持する。
- 武器種・特殊弾以外の回路補正は従来の積載設計どおり運ぶ側に加算する。降ろすと加算が消える。小隊効果は既存の集計で数え、二重に加算しない。
- PR4 carried-aimで更新（2026-10-17）：対象が積んでいるコンテナ／機体は、8秒の積載完了時にすべて地面へ降ろす。容量に余裕があっても運ぶ側へ移さない。装備回路・自身の弾薬・活動量は保持。機体の入れ子・循環積載は作らない。
- 搭載機が大破しても残骸として積載状態を保つ。運ぶ側が大破すると積荷を落とし、生存搭載機は通常の回路・指示に従う独立移動に戻る。

## 移動活動量

- 実際に移動した時間1秒につき活動量1を消費する。積載量による追加の毎秒倍率はない。速度120→60なら同じ距離を進む時間と消費量は2倍。
- 停止・射撃・回収待ち時間・搭載機の移動消費は0。搭載機の射撃は自身の弾薬を消費する。
- 活動量が尽きると機体は残骸化（HP0・alive=false）。運ぶ側が尽きた場合、生存搭載機を解放する。残った活動量分だけ移動でき、0未満にはしない。
- 出撃中の上限補正とreleaseの能力倍率は維持する。実効活動量＝保存活動量÷基礎容量×出撃中容量。消費1秒は実効活動量1に対応し、HUBへは倍率を戻した基礎容量・残量を保存する。容量バフを重ねて保存しない。
- 活動量は小数を保持する。途中保存とHubSaveでは数値の小数を維持し、compact URLは小数点以下6桁まで送る。整数の旧セーブ／旧URLも読める。バッテリー項目が無い開発／旧URLは架空の帰還バッテリーを作らず従来の動作を保つ。
- 敵の既存の活動量・補給・10%時の固定砲台化は今回変更しない。

## HUB充電

- 機体ごとの「充電」ボタンで、電力パーツ1個につき基礎活動量1を充電する。クレジット・装甲・弾薬は消費しない。
- 在庫の範囲で満充電し、不足時は途中まで充電して案内する。すでに満充電の機体は支払わない。最後の小数の不足はパーツ1個で満たし、容量を超える分は切り捨てる。
- 充電で装甲や大破状態は回復しない。残骸復活・通常修理は既存の別操作。
- 保存に失敗した場合は元の状態を保ち、パーツを消費したことにしない。出撃時の自動充電は行わない。

## 保存互換

積載先は既存のWorld.circuitPlay.carry（機体ID→搭載対象IDの配列）を使い、生存機体も同じIDで記録する。旧形式のcarriedと残骸だけの途中保存は既存の移行を保つ。新しいHubSaveトップレベルキーは追加しない。battery.activityだけ小数を許可し、capacityは従来どおり整数。旧ビルドで保存し直すと活動量の小数が切り捨てられ、生存機体の積載も保持できないため、この変更を含むビルドを使う。

## PR #328 CORRECTION：残骸化時の資源

新しい味方の戦闘大破・活動量切れは、残弾と残存活動量を現地の弾薬/電力ドロップにし、残骸の対応残量を0にする。活動量の出撃中補正は既存effectiveBatteryCapacityの単位を使う。コンテナ投下、生存搭載機の解放、回路の機体への装着は既存の別処理のまま。処理済み印は途中保存され、既存の死体を読み込んだだけでは新しい資源ドロップ/残量移行を行わない。活動量切れ直前HPからの装甲ドロップは、換算と端数の神宮確認待ち。
