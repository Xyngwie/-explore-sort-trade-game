# 盾システム検証用デバッグモード

仕様源: 神宮提示の [SPEC_DECISION](spec-questions/shield-debug-decision.json)。基準mainは `f53788cb19b4b61d29663d66f50accfc9de4e05c`（#317）。この変更はDraft・監査待ち。マージ・デプロイは行わない。

## 入口と操作

HUBの先頭にある「開発・検証用：盾システム」を開き、「盾検証モードへ入る（専用セーブ）」を選ぶ。検証画面は常に `DEBUG_FIXTURE` と表示する。プリセットを選んで「テスト開始」を押すと、Exploreの出撃途中セーブを準備し、一時停止状態で開く。タップで再開する。通常の出撃ルールを変更しているのではなく、承認されたテスト状態を出撃途中として読み込む。

検証画面のコンソールには、手順、盾ID・HP・最大HP・所有先・機体・回路・途中作業を確認する操作、JSON証拠出力、選択したプリセットの初期化・再生成、通常HUBへ戻るリンクがある。コンソールはアプリの再描画から独立している。隊長/僚機の回路装備の変更は検証用HUBの既存の個別装備UIを使う。通常の装備カテゴリ制限は解除しない。

| プリセット | 準備する状態・期待する操作 |
| --- | --- |
| NO_SHIELD_NO_CIRCUIT | 所持盾・回路なし、近くに地面盾。盾をタップ→一覧→2秒で拾得。剥離・屹立は使用不可。 |
| NORMAL_SHIELD_AND_RESERVE | 隊長に装備盾と予備盾。前方の敵は通常の満タン弾薬の初期状態。静止して盾防御・破壊・別2秒の予備交換を確認。敵のAIやダメージ式は変更しない。 |
| STRIPPING_READY | 隊長に有効な通常盾回路。近くの敵残骸に通常盾回路効力12.75。残骸盾→対象をタップ→8秒剥離、最大耐久62.75。別2秒で拾得。 |
| P_SHIELD_LEADER_READY | 隊長だけに配線済みP盾回路と装備盾。2秒で屹立、移動遮断、設置盾をタップ→撤去2秒→地面盾をタップ→拾得2秒。 |
| P_SHIELD_WINGMAN_READY | 僚機だけに配線済みP盾回路と装備盾。僚機を選択→屹立。隊長の屹立は使用不可。 |
| BARRICADE_PERSISTENCE_READY | 設置済み盾、僚機の建設0.75秒、隊長の剥離3秒を準備。再読込中は進まず、タップ再開後に残り時間で完了する。 |

作業時間・HPは通常のゲーム処理を通る。地面盾17.25/62.75、装備盾47.25/62.75、予備盾35.5/50など、小数を含む識別可能な値を使用する。各盾のID・生成順は既存のID発行関数で生成し、所有場所は一つだけにする。

準備した検証セーブは2機、必要な装備枠を満たす5段進行、同じ共有盤面のHQマスを使う。テスト地点は(600,600)、搭乗円も同地点、回収済みコンテナ1個を容量の空いた機体に保持させ、帰還・精算を検証できるようにする。通常セーブの段位や報酬は変更しない。通常HUBへ帰還した後の再出撃は通常の出現位置を使うため、現地の盾まで移動するかコンソールの位置表示で保存状態を確認する。

## 保存の隔離

- 明示的なURL `debug_fixture=shield` のある画面だけで有効。グローバルなモード切替は保存しないため、通常プレイの別タブは通常領域を使い続ける。
- 起動の最初にlocalStorageとsessionStorageのアクセスを、`wreckline.DEBUG_FIXTURE.shield.v1:` プレフィックスの専用領域へ切り替える。HUBの帰還トークン検証も切替後に行う。
- 通常セーブの読込・コピー・フォールバックは行わない。clear、列挙、プロパティ形式のアクセスも専用領域だけに作用する。切替失敗時は起動を中止し、通常セーブで続行しない。
- HubSave、途中セーブ、Restoreの配線、帰還トークン、ログ履歴も同じ隔離対象。各モジュールへのリンクには検証フラグを引き継ぐ。通常モードへの復帰はフラグと引継ぎクエリを外したHUBリンクで行う。
- プリセット開始・初期化は検証領域だけを置き換える。開始ごとにrun IDを発行し、同じURLの再読込では初期化しない。建設/剥離などの残り時間は既存チェックポイントで保存する。
- 検証用データも保存先は同一ブラウザープロファイルに1組。同じプロファイルの複数の検証タブで同時に初期化しない。通常タブとの同時利用は保存領域が異なる。
- これは第三者検証用の入口であり、秘密の管理者権限や認証機構ではない。検証用アイテムを通常領域へ持ち出す機能は用意しない。

デバッグ用メタデータは専用領域の `DEBUG_FIXTURE.meta` に保存する。結果画面にもコンソールのラベルが残り、証拠JSONには `type: DEBUG_FIXTURE`、プリセット、run ID、日時、検証領域の保存内容と実行中の状態を含める。物理スマートフォンかエミュレーションかはテスターが別途記録する。

## 第三者検証

1. 通常HUBの資金・機体・倉庫を記録する。
2. 明示的な入口から検証モードに入り、各プリセットを実行する。画面内の期待手順を使う。
3. 「盾ID・HP・所有状態を確認」で所有先が一つであることを確認し、途中でJSON証拠を出力する。
4. 作業途中に再読込し、再開まで時間が進まないことを確認する。
5. 帰還要請→搭乗→結果→格納庫→再出撃で同じマスの盾ID/HPを確認する。初期化ボタンは保存確認が終わるまで押さない。
6. 検証モードを終了し、手順1の通常データと照合する。

[第三者チェックリスト](SHIELD_THIRD_PARTY_CHECKLIST.md)の通常入手経路の確認と、デバッグデータを使った機能検証は分けて記録する。

## 再実行と結果

全5ビルドをGitHub Pagesと同じベースパスで作成した後、以下で同一オリジンのローカル本番プレビューと390×844の実操作テストを起動できる。スクリプト自身が一時HTTPサーバーを起動/終了し、通常セーブをシードした隔離ブラウザーを使用する。アプリへfixtureを注入せず、ゲーム画面の入口とプリセット操作で準備する。

```sh
VITE_BASE=/-explore-sort-trade-game/ npm run build:trade
VITE_BASE=/-explore-sort-trade-game/explore/ npm run build:explore
VITE_BASE=/-explore-sort-trade-game/sort/ npm run build:sort
VITE_BASE=/-explore-sort-trade-game/invade/ npm run build:invade
VITE_BASE=/-explore-sort-trade-game/restore/ npm run build:restore
node scripts/verify-shield-debug.cjs
```

Playwright Coreを別の場所へ導入している場合は`PLAYWRIGHT_MODULE`、Chromiumの場所は`CHROMIUM_PATH`で指定する。ローカルViteの分割ポートは元のゲーム同様にブラウザーの保存領域を共有しないため、帰還・再出撃の統合確認は上記の同一オリジンプレビューを使う。

最終検証結果は [shield-debug-mode.json](verification/shield-debug-mode.json) とPR本文へ記録する。物理端末と公開版の新機能テストはNOT_RUN（未デプロイ）。
