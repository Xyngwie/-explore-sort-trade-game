## 9. U-2：SORT（同じページ・同じ canvas）

### 9.1 しくみ

- ページの URL に、既存の SORT のページと同じクエリ（`salvagedContainers`・`totalStockPieces`・`isExtracted`・`introOpening` など）を載せる。新しい URL のキーは足していない。SORT にしかないキーがあれば SORT、無ければ DOCK を出す（`craftMultiplier` は帰りの URL にもあるので判断に使わない）。
- DOCK → SORT と SORT → DOCK は、ページの読み込みではなく、同じページの履歴（`history.pushState`）の移動。描き直すのは同じ canvas。再読み込みすると、同じクエリで同じ局面に戻る（SORT の途中保存は既存どおり、局面が変わったときの盤）。
- 既存の守りは、既存のページと同じ順で呼ぶ（中身は既存のファイルから副作用のない関数として切り出しただけで、既存のページもその関数を呼ぶ）。

| 場面 | 呼ぶもの（既存） | 切り出した先 |
|---|---|---|
| DOCK → SORT | `launchSortFromUnopened`（コンテナの予約・開封 ID・戻る用の印） | — |
| SORT の開始 | `armSortBackTrap`（出撃の完了印が無い間は戻るを吸収） | — |
| SORT の中 | 盤（`refine.ts`）、途中保存 `wreckline.sortSession.v1`、導入中の開封 ID の照合と結果の保存（`completeIntroOpening`）、`sort.<局面>` の記録、点滅 → 落下のタイマー（保存中は待つ）、スワイプ 16px・タップ選択・矢印キー | `sort/src/canvas/sort-scene.ts`（規則は `main.ts` と同じ） |
| ＋1・＋ALL 未開封 | `spendHubContainers`・`addContainersToQuery` | `sort/src/hub-container-core.ts` |
| SORT → DOCK | 1 回限りのトークン（`handoffId`、URL の完全一致） | `sort/src/handoff-core.ts` |
| DOCK の受け取り | トークンの照合（無効なら付与のキーを消す）→ 最後の精製量の記録 → 戻る用の印を消す → `ingestLocationSearch` → クエリを消す | `trade/src/sort-return-core.ts` |
| SORT から戻る | 完了印があるときだけ DOCK へ。予約したコンテナを返す（既存の `pageshow` の back_forward と同じ処理） | `trade/src/sort-return-core.ts` |

- SORT 中の下部タブは、既存のシェルと同じくすべて無効（#332：受け渡しの途中でタブから離れない）。
- 探索 → SORT（出撃の帰り）は、探索が canvas に移るまで既存版の SORT のページのまま。

### 9.3 既存版から変えた点・注意

- 既存版で `window.confirm` の無い SORT には、確認ダイアログを足していない。
- 「デモクエリで開く」は、同じページでデモの SORT を開く（既存は SORT のページで開く）。

- 保存中（記録を保存しています…）は、既存と同じく盤もボタンも反応しない。

### 14.6 #351 の Bugbot 指摘 2 件の修正（2026-11-06・監査より）

1. **同じページのまま探索を離れると、チェックポイントが書かれなかった**（High）
   - 既存のページでは、「仕分へ」「格納庫へ」やタブで離れると `pagehide` で途中保存（結果なら結果）を書いていた。同じページ内の移動では `pagehide` が起きない。
   - 修正：アプリが探索のシーンを閉じる前に、`pagehide` と同じ途中保存（`persistOnHide(false)`）を書く。
   - 調べたこと：canvas のページではプレイ記録がいつも動いている。探索のシーンはプレイ記録に今のチェックポイント（`setPlayLogCheckpointProvider`）を渡しており、プレイ記録は次の記録のときにそれ（結果）をチェックポイントに書き戻す。そのため、指摘の「終わった出撃を再開する」状態は、今のアプリではプレイ記録が先に防いでいて、ブラウザでは再現できなかった（古い出撃のチェックポイントを置いて離れても、修正の有無にかかわらず「結果」に置き換わった）。修正は、プレイ記録の書き戻しの時機に頼らないための安全策として入れた。
2. **一時停止の覆いが、対象選択のダイアログを遮っていなかった**（High）
   - 覆いは操作ボタンと同じ層の領域だった。ボタンへのタップは、接触の振り分けで覆いが先に取っていた。しかし対象選択のダイアログは上の層なので、その行へのタップは選択として動いていた。
   - 修正：覆いを、ダイアログより後に描く専用の最上層にした。シーンの操作も一時停止中は何もしない。「次のタップは再開だけ」が、ボタン・地図・スクロール・ダイアログのどれでも同じになる。

検証：
- `canvas-explore.selftest.ts`：一時停止中は、覆いが最上層でボタンの下に入る（「帰還要請」は動かず、一時停止のまま）。対象選択のダイアログの行も動かない。結果の画面で離れると、出撃のチェックポイントが残らない。
- `verify-canvas-explore.cjs`（5 構成）：一時停止中に「帰還要請」をタップすると再開だけで、帰還要請は出ない。コンテナを持ち帰った状態（完了の印なし）を作ってから「仕分へ」で離れると、出撃のチェックポイントが残らない。
  - この「仕分へ」の確認は、修正前のアプリでも通る（上のとおりプレイ記録が書き戻すため）。結果の状態を守る確認として残した。
  - 一時停止の覆いの確認は、ボタンについては修正前でも通る（接触の振り分けで覆いが先に取っていた）。ダイアログの行が止まることは selftest で確かめた。

### 16.4 既知の制限

- Alpha Lab の帯は、探索のシーンがあれば今の世界を「確認」できる。ただし、出撃中の世界をその場で書き換える機能（既存の探索のページの `createAlphaLabHost`）は、canvas 版にはまだつないでいない。帯の中の「検証モードへ入る」は、既存版のページへ移る。
- 欄の中は HTML なので、canvas 版の約束（ゲーム内は canvas だけ）の例外になる。開発版だけに出す。

### 16.5 検証

- `canvas-ui.selftest`：欄を出す条件（localhost・127.0.0.1・`?debug=1`。公開版の素の URL と `?debug_fixture=shield` では出さない）。

### 16.6 #353 の監査の修正（2026-11-07）

1. **B1 新規ゲームで `?debug=1` が消えていた**：移動先が canvas のページの URL（クエリなし）だったので、公開版で新規ゲーム・デモ初期化をすると、次の読み込みで欄が消えていた。直した後：`?debug=1` で開いていたときは、移動先にも `?debug=1` を付ける（`canvasNewGameDestination`）。`debug_fixture` などほかのクエリは付けない。localhost・127.0.0.1 は付けない。
2. **B2 SORT・探索の検証用の操作に届かなかった**：欄を開くボタンが DOCK にしか無く、SORT はタブが無効、出撃中はタブが隠れるので、DOCK から欄を開いていないと、SORT のテストプレイや探索の回路ロックの切り替えに届かなかった。直した後：検証用の欄があるときは、SORT と探索にも「検証用の欄へ ▼」を出す。操作そのものは今までどおり欄の中だけ。
3. **B3 欄を開くと、canvas がページのスクロールを止めていた**：欄を開いてページがスクロールするようになっても、canvas の上ではタッチのパンとホイールを canvas が取っていた。さらに、`html` と `body` の両方をスクロール可能にしていたため、ページの `overscroll-behavior:none` でホイールがページまで届かず、欄の上でもホイールが効かなかった。直した後：
   - 欄が開いている間は、canvas は入力を取らない（`CanvasSurface` の `inert`）。`touch-action:pan-y` にし、ホイールも止めない。開くときは、押している途中の操作を取り消す。
   - スクロールするのは `html` だけにした（`body` は `overflow:visible`、`overscroll-behavior:auto`）。
   - 閉じている間は今までどおり（ページはスクロールせず、canvas が入力を取る）。
   - CSS は欄の部品が入れるので、canvas の 4 つのページすべてに効く。
4. **B4**：`debug-panel.ts` の見出しの節番号を §16 に直した。
5. **B5 欄を開いていても、キーがゲームに届いていた**：`inert` はポインタとホイールだけを止めていて、window の keydown / keyup は canvas のキーと探索・SORT のキーに届いていた。探索は Space などで preventDefault するので、欄を開いた出撃中も移動と射撃が入り、Space でページをスクロールできなかった。直した後：
   - 欄が開いている間は、canvas（`CanvasSurface` の `inert`）も探索・SORT（`routeGameKey`）もキーを受け取らない。preventDefault もしない。Space はページのスクロールに残る。
   - 開くときは、押したままの探索のキーを離す（`releaseHeldKeys`）。keyup は欄が開いている間は届かないので、離しておかないと移動と射撃が残る。
   - 閉じている間は今までどおり（Escape はモーダルを閉じる。探索のキー、SORT の矢印は今までどおり取る）。

検証：
- `canvas-ui.selftest`：新規ゲームの移動先（公開版 `?debug=1` → `?debug=1` だけを残す、ほかのクエリは付けない、素の URL・localhost はそのまま）。欄が開いている間は window のキーが canvas に届かず、Space も Escape も止めない。閉じている間は Escape がモーダルを閉じ、Space は canvas のキーではない。
- `canvas-game-keys.selftest`：欄が開いている間は探索の keyDown / keyUp と SORT の key を呼ばず、preventDefault しない（Space・WASD・F・矢印）。閉じている間は今までどおり（名前欄では探索のキーを取らない。保存中は SORT のキーを取らない）。
- `canvas-explore.selftest`：出撃中に押したままの W は、`releaseHeldKeys` のあと移動を続けない。
- `verify-canvas-explore`（PC）：欄を開いている間は W で隊長が動かず、Space は preventDefault されずページがスクロールする。閉じると W は再び動く。
- `canvas-sort.selftest`・`canvas-explore.selftest`：欄があるときだけ「検証用の欄へ」が出て、押すと欄が開く。検証用の操作は canvas に無い。
- `verify-canvas-dock-full`（5 構成）：欄を開いたあと、canvas の上でページを上へスクロールでき（PC はホイール、タッチの構成は指のドラッグ）、canvas の上から下へスクロールして「▲ ゲームへ」に届く。修正前のコードでは、この確認が落ちることを確かめた。
