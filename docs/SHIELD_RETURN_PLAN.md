## 実装

- 通常離昇・帰還失敗・手動救助・両時間切れ経路で、既存の機体分類が終わった後に盾の精算を一度だけ実行。生存機の置き去り判定や機体受領・コンテナ・回路・費用は変更しない。
- 帰還対象の装備/予備/交換中の盾を各機体位置へ強制投棄し、交換/回収予約を解除。既に死亡時に落とした盾は重複投棄しない。
- 置き去り機の盾はHubSave任意lostMechShieldsに機体instanceIdで紐付け、正規レジストリの安定キーを参照。HP・個体ID・出自・生成順・装備/予備の区別・取得順を維持。
- 交換はuntilの絶対値を保存せずremaining秒で保存。例：残り0.75秒なら、次のWorld.elapsed=0に対する期限0.75秒。新しい良い予備があっても再選択しない。予約中は重量を占め投棄禁止。checkpoint再読込でも残りを維持。
- 再登場する置き去り機は既存のpassiveなstrandedMechsのまま。盾の参照/交換処理に必要な軽量の所有者ビューを用い、新しい戦闘AIや命令・表示仕様を追加しない。
- 再登場機が後の出撃で回収された場合も盾を現在位置へ落とし、HUBへ盾を持ち込まない。消えた機体への所有参照を残さない。
- 帰還payloadの既存fieldCellへ任意ownedShieldsを加え、直接保存/帰還URLのsortieId精算に接続。結果checkpointで省かれる敵情報は既存の退避報告を維持しつつ、盾の状態を失わない。
- groundと所持の重複、参照切れ、不正な交換状態はセーブの黙った削除ではなく読込拒否。旧セーブのフィールド欠損は欠損のまま。
- 盤面再生成では既存の地面盾消去・IDカウンター維持と、所持盾/交換状態を区別。既存の置き去り機の新盤面への移動をそのまま使用。
