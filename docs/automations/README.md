# Cursor Automations に貼る指示文

新しいエージェントは、前のチャットを知らない。Instructions と、リポジトリの [`../AGENT_BRIEFING.md`](../AGENT_BRIEFING.md) だけが判断の引き継ぎである。

この指示文が効くのは、`AGENT_BRIEFING.md` がエージェントの読む `main` に入ったあとである。ブランチ上にあるだけでは、`main` をチェックアウトした起動は古い案内のままになる。

## トリガー

実装のリレーは Issue コメント、または同じ JSON が届く Slack を想定する。1 回の応答は JSON 1 個で、届いた場所にだけ返す。

Issue コメントトリガーは、`github-actions[bot]` と GitHub App のコメントでは起動しない。GitHub Actions が bot として次の JSON をコメントしても、次のエージェントは起きない。無人でつなぐときは、ユーザーの PAT で人間のアカウントとしてコメントするか、Issue コメント以外の Webhook で同じ JSON を渡す。

送ったことと、次が起動したことは別である。起動の証拠は、次のエージェントの応答だけである。

## 注文でないもの

「実装の開始ではありません」、`notAnOrder: true`、待機、記入例、自分以外への宛先は、実装を始めない。`title` と `details` だけの `SPEC_DECISION` は形としては有効で、2026-10-09 の README へ 1 行足すテストは、実装の開始ではないので着手しない。

「不具合報告ではありません」は、Slack の不具合報告自動化を止める定型である。注文を捨てる条件ではない。作業連絡の先頭には、この文と「他の実装エージェントは着手しない」を置く。
